# sdlc-intent 体检 v2.0：从六层审读 到 三引擎体检

> 决策记录。回答一个问题：**为什么 v1 体检会漏掉一整类缺陷，以及 v2 用什么架构补上**。要改体检维度、检查项或引擎前先读本文。
>
> 状态：批0（本文）+ 批1（第 7 层维度 / missed-patterns 回流库 / eval-6）+ 批2（阶段0 参照系 / ref-tables / D1·D3 标注 / 漏检比对入口）+ 批3（perspectives 视角推导 / 扇出与轻重路由 / scan_refs.py 脚本化 / D2 标注）已全部实施——三引擎齐备。

## 1. 背景：一次漏检复盘

真实案例（脱敏概述）：一份区域级统计报表类需求——多平行组别、大量计算指标、附 600KB 级 HTML 原型。v1 体检产出 40 条命中，开发者事后人工补提 26 问，其中 **11 条完全漏检**，3 条被产品确认为真需求缺口（隐藏统计口径、缺失配置项、整板块需求缺失）。

对 11 条漏检逐条归因后发现它们共享同一性质：**没有一条是"写了但写错"，全部是"该写而没写"**。而 v1 的六层维度全部是文档内部一致性检查（两处规则互斥、状态不闭环、字段引用不存在……证据都在原文里）——对"没写的东西"，通读得再仔细也查不出来。

## 2. 心智模型：两类缺陷，oracle 位置不同

| | 写错类缺陷 | 缺失类缺陷 |
|---|---|---|
| 例子 | 规则互斥、状态不闭环、歧义句式 | 指标无定义、配置项缺失、数据无来源 |
| oracle（判定基准）在哪 | **文档内部**（两处原文互为证据） | **文档之外**（平行结构、原型、实现视角、数据血缘、外部系统） |
| 检查动作 | 通读 + 模式匹配 | **先构造参照物，再拿文档去对** |

推论：缺失类检测 = 构造参照系 + 双向 diff。人工专家不是记忆力更好的清单，而是带着外部参照系在推导（"这数据从哪来""这指标怎么算"）——skill 要复刻的是参照系的构造方法，不是更多检查条目。

依据：PBR（Perspective-Based Reading，Basili/Shull）实证表明视角化审查显著优于清单式阅读，且对不熟悉应用域的审查者效果最显著——恰是 LLM 每次面对新业务域的处境。

## 3. 三引擎架构

```
引擎一（句子级）  六层维度（现有）      → 抓「写错的」，角色从唯一探测器降为守门
引擎二（结构级）  参照系构造 + diff     → 抓「可机械发现的缺失」（批2 落地）
引擎三（视角级）  PBR 推导任务子代理    → 抓「机械方法发现不了的缺失」（批3 落地）
                                    三路命中汇合去重后出报告
```

引擎间不是替代关系：引擎一抓到的互斥/断链（如两处口径冲突）仍是高价值命中；引擎二把缺失检测变成"表格对齐"；引擎三用实现者/测试者视角的推导任务暴露 unknown-unknowns。

## 4. 批1（已实施）：第 7 层「外部参照层」

不改引擎架构的前置止血：把 5 类漏检模式收编为 dimensions.md 第 7 层的 6 个检查项（**独立成层而非散插六层**，因为它们的检查姿势本质不同——需要先构造参照物）：

| 检查项 | 一句话定义 | 本次漏检对应 |
|---|---|---|
| 有录无消 | 字段有录入入口但全文无消费方 | 隐藏统计口径（字段维护了但分隔规则正文零提及） |
| 有消无录 | 计算/展示引用的输入无处配置 | 缺失配置项（指标被计算但划线设置无入口） |
| 数据无源 | 被依赖的对象/数据无来源与入口 | 外部数据依赖（关键数据从哪来无说明） |
| 引用断链 | 「下文另行说明」无落点/被引板块无定义 | 整板块需求缺失（板块被引用但无章节） |
| 对称缺格 | 平行维度成员缺兄弟模块的功能面 | 平行模块横向缺口 |
| 跨模块不对齐 | A 处集合与 B 处集合的匹配规则未定义 | 跨模块数据一致性 |

配套纪律（防误报，与全局"严重度从严"显式区分）：**第 7 层的从严适用于是否记录，不适用于级别**——拿不准级别时降一级并注明；每个检查项有证据要求（如有录无消须附字段全文出现位置清单，否则降建议级）。

## 5. 批2：四张参照表（引擎二）

体检阶段 0 产物 `refs-<YYYYMMDD>.md`（**不进 digest 8 区块**——digest 是给用户确认的共识产物，参照表是检查脚手架；也不动 sdlc-sync payload 契约）。原料 = digest 的概念表/功能点地图/规则表 + doc.json 块模型。

| 表 | 行 × 列 | 命中规则 |
|---|---|---|
| 数据字典 | 字段 × 录入处/消费处/来源 | 有录无消（消费列全空）/ 有消无录（录入列空）/ 无源（来源列空且非本系统录入） |
| 指标字典 | 指标 × 公式/输入/配置入口/精度/落点 | 任一列空即候选 |
| 平行结构矩阵 | 对称维度值 × 功能面 | 缺格且兄弟成员有（正文显式声明有意差异的不命中） |
| 引用图+外部依赖 | 引用语句→落点；外部系统清单 | 断链；未声明的外部依赖 |

裁剪：无平行结构不建矩阵、无计算指标不建指标字典——参照表按触发特征构造，小需求只建数据字典。

## 6. 批3：视角推导子代理（引擎三）

- **derivation task 而非提问清单**：实现者视角推"数据从哪来/存哪去/与哪些系统交互"；测试者视角对每条 FR 推验收断言与边界值——缺陷是推导的副产品
- **收敛纪律（生死点）**：每个候选问题必须回原文做块级锚点定位，**找不到定位才保留**（把"命中必须附原文定位"纪律反向使用，天然抑制泛泛而问）；阶段 0 表上已现形的不重复报
- 喂料纪律复用 sdlc-gate 先例：子代理只喂「模块切片 + 相关表行 + 任务卡」，不喂全文（防交叉污染 + 抗长上下文注意力衰减）
- 重需求才扇出（见 §8 路由）

## 7. 横切机制

**冲突处置总原则：体检不裁决冲突，冲突即发现。**
- 源间不一致（评论 vs 正文 / 原型 vs 正文）：记命中交 PM 裁决，不静默择一（梳理阶段"以最新评论为准"仅用于忠实转述）
- 批1 最小版：第 6 层「评论结论未同步正文」加升级规则——结论性口径互斥升 🟡 标「源间冲突待裁决」
- 批2 完整版：构表时同概念两处口径不一律写 `⚠️冲突[出处A|出处B]`，禁止择一填入；依赖冲突格的下游行标「依赖待裁决」，视角推导遇待裁决格只追问不假设

**上下文工程**（长需求防注意力衰减/指令漂移/自我污染）：
- 产物落盘、上下文按阶段重建——阶段间传结构化摘要+命中清单，不传全文
- 块级锚点当索引用：定向读代替通读，上下文占用从 O(全文) 降到 O(当前检查对象)
- 机械部分脚本化（批3）：doc.json → 参照表 → 空格/断链/冲突扫描用脚本做（复用 doc-pipeline / guardrails check.py 先例），LLM 只做语义判定；锚点真实性可硬校验
- 路由分级本身是质量措施：本次漏检集中在长文档中后段

**missed-patterns 回流管道**（`references/missed-patterns.md`）：漏检模式 backlog，维护者侧资产、不注入体检 prompt——治漏报的运行时机制就是维度表条目本身；与 sdlc-gate 的 false-positive-patterns（运行时注入防重报）语义成对偶：**一个治误报，一个治漏报**。每次漏检归因入库存，同类重复 3 次或单次阻断级漏检 → 升级为维度表正式条目。

## 8. 路由分级

对齐 large-req-playbook 触发条件（功能点 ≥5 / 跨域 / 涉表）：
- **轻需求**（功能点 <5 且无计算指标且无平行结构）：阶段 0 只建数据字典 + 七层顺序跑，单会话
- **重需求**：全三阶段，视角推导扇出全新上下文子代理
