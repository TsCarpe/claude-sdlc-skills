# DDL/DML 分级规则（模式 E 配套）

模式 E 提取到语句后，按本表标执行时机。分级只依赖语句关键字与目标表新旧，可静态判定；判定不了的走文末「人工确认情形」。

## 分级表

| 级别 | 语句特征 | 执行时机 | 依据 |
|---|---|---|---|
| 🟢 前置 | `CREATE TABLE`；`ALTER TABLE ... ADD COLUMN`；新表上 `CREATE INDEX`；加注释/加默认值 | 部署前 | 新代码依赖新结构，漏跑 = 启动失败或运行时报错 |
| 🔴 后置 | `DROP TABLE` / `DROP COLUMN` / `DROP INDEX`；`RENAME TABLE` / `RENAME COLUMN`；`MODIFY` / `CHANGE`（列类型变更）；`TRUNCATE` | 部署后或下轮发布 | 旧代码还在读写旧结构，部署前执行 = 旧代码立即报错 |
| ⚠️ 大表风险 | 存量表上 `ADD INDEX` / `ADD COLUMN` | 低峰执行或在线 DDL 工具 | 锁表风险随数据量放大，需评估 |
| 🟡 订正 | `INSERT` / `UPDATE` / `DELETE` / `MERGE`（回填与数据订正） | 部署后、验证前 | 供新代码读取的数据必须在新代码验证前就位 |

## 判定规则

- 同一语句同时含 ADD 与 DROP/RENAME/MODIFY（如 `CHANGE COLUMN a b INT` 含改名+改类型）→ 按 🔴 后置处理（保守原则：就高不就低）
- `IF NOT EXISTS` / `IF EXISTS` 前缀 → 仍列入清单；幂等性不改变时机分级
- 多语句文件逐语句分级——同一文件可同时出现 🟢 与 🔴（加列+删列同脚本），按各语句时机拆开列，🔴 部分注明「待旧代码全下线」
- 「新表」判定：目标表在同一 diff 中由 `CREATE TABLE` 新建 → 其上的 `CREATE INDEX` 算 🟢；无法判断表是否新表 → 标 ⚠️ 大表风险，人工确认
- 订正脚本的依赖无法静态判定（不依赖新结构可部署前跑；依赖则必须部署后）→ 默认 🟡 部署后、验证前，建议操作注明「按脚本注释确认时机 + 确认幂等可重跑」

## 噪音排除（模式 E 专用）

- 注释：`--` 行注释与 `/* */` 块注释内的语句
- 事务控制：`BEGIN` / `START TRANSACTION` / `COMMIT` / `ROLLBACK`
- 只读语句：`SELECT` / `SHOW` / `EXPLAIN` / `DESC` / `DESCRIBE`
- 环境语句：`SET` 会话变量、`USE` 切库

## 人工确认情形（尾部提示，不计入清单）

- 存储过程 / 函数 / 触发器体内的动态 SQL——静态不可判定
- 不在 diff 内的数据库变更（DBA 平台侧操作、其他分支先行执行的脚本）——本清单只覆盖 diff 中的 `.sql`，提示「平台侧已登记的变更需人工核对」
