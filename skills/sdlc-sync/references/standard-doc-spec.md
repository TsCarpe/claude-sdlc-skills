# 标准需求文档合成规范（重写版 v1.1）

> 适用：sdlc-sync `publish` 动作合成 standardMd 时遵循。
> 依据：REQ D6 + 需求方澄清（2026-09-18）：**以原始需求全文为底稿**，整合体检定论与澄清答复，产出完整可用的需求定稿。
> 一句话：把「原文快照 + 体检定论 + 澄清答复」整合成一份**开发可直接开工、AI 可独立读懂**的需求文档。

## 0. 目标（验收口径）

1. **开发可用**：拿到这一份文档即可开工，不需要回飞书原文，不需要翻 31 条澄清记录对照。
2. **AI 可读**：AI 只读这一份文档即可获得——
   - **全貌**：功能模块与业务规则全集（原文规则的完整承载，不是摘要）；
   - **边界**：本期范围、明确不做、角色权限边界、遗留假设口径；
   - **逻辑**：状态机流转、字段×状态矩阵、校验链、时间依赖等，以结构化文本表达、可被程序解析。
3. **可追溯**：每处整合有 ✅/⚠️ 标注与引用记号，裁决过程保留在附录。

## 1. 底稿与输入

| 材料 | 用途 |
|---|---|
| **原文快照**（push 时 lark-cli 拉取的飞书全文） | **底稿**。正文的规则全集必须等价覆盖原文，不得因"整合"丢内容、丢细节、丢例外条款 |
| digest（FR 注册表/功能地图/假设清单） | 章节组织索引 + 假设口径来源；骨架是索引，**不是内容上限** |
| audit（问题明细 + go 定论） | go=✅已确认 的定论合入正文；go=跳过 不改正文 |
| 澄清清单 + 平台已答复（pull-answers 后） | 逐条消化的主要输入 |
| cases.md（可选） | 仅用于核对术语与编号，不改变需求内容 |

## 2. 文档结构

```
# <需求名> · 标准需求文档（定稿）
元信息头：需求编号 ｜ 迭代 ｜ 版本 ｜ 合成时间 ｜ 质检依据快照时间 ｜ 答复进度 n/N ｜ 废弃条款数

一、需求概述与边界
   1.1 概述（原文简述 + 本轮范围变化）
   1.2 本期范围 / 明确不做          ← 边界
   1.3 术语表（体检定论统一后的命名）  ← 逻辑/全貌
   1.4 角色与职责（含权限边界）

二~N、按业务域组织的定稿正文          ← 全貌 + 逻辑的主体
   （以原文章节结构为基础逐域整合；每域内：）
   - 规则正文：原文规则 + 已答复结论合入（✅ 标注 seq）
   - 废弃条款：~~删除线~~ + 定案说明（如"总则句废弃，以 需求.FR-32 为准"）
   - 未答复/字面待复核：按假设口径行文，⚠️ 标注
   - 逻辑载体文本化：状态机流转表、字段×状态矩阵、校验规则（阈值/枚举/依赖）、时序约束

N+1、遗留假设汇总（需求.Axx，⚠️）     ← 边界的兜底清单
N+2、附录：澄清结论表（seq/级别/问题/结论/影响范围） ← 裁决记录，全文引用的落点
```

全文保留引用记号：`需求.FR-xx`、`体检.Pxx`、`需求.Axx`、裸 `Pxx`——平台渲染时自动链接化（D7）。

## 3. 消化规则

1. **逐条消解**：每条已答复澄清 → 定位原文对应规则位置 → 把结论合入正文 → 标 `✅（Pxx）`；结论影响多处时处处标注。
2. **冲突裁决**：结论与原文冲突时以结论为准，原文表述按废弃条款处理（删除线 + 说明），不并排保留两版。
3. **❓ 清零**：原文与 digest 中一切 ❓/待定记号必须消解——定案（✅）或转假设（⚠️ + 需求.Axx）二选一，不得残留。
4. **不发明需求**：合成只整合、不新增。合成过程中发现的真空白 → 写入遗留假设并标注，不得静默替需求方决策。
5. **跳过项**：audit go=跳过 的问题不改动正文；若其内容已按假设行文，在遗留假设中体现。
6. **原文优先保真**：原文的具体数值、枚举、例外条件一个都不能丢；结论只改变"被裁决的那一处"。

## 4. 质量自查清单（合成后逐项过，再给用户过目）

- [ ] 原文快照的每条规则都能在文档中找到落点（对照快照逐节扫一遍）——全貌
- [ ] 本期范围 / 明确不做与 digest 一致——边界
- [ ] 状态机、矩阵、校验链、时间依赖在正文中完整且自洽——逻辑
- [ ] 全部澄清问题有着落：正文 ✅ 或附录裁决记录可查
- [ ] ❓ 清零；⚠️ 仅限真实未定案/字面待复核项，且汇总在遗留假设
- [ ] 引用记号抽查：FR / 体检.P / 需求.A / 裸 P 四类都能对得上号
- [ ] 通读无"见飞书原文 / 见原型 / 详见附件"类外指依赖（自包含）
- [ ] 元信息头完整（快照时间必填——它是"依据版本"的锚）
