# 标准需求文档合成规范（重写版）

> 适用：sdlc-sync `publish` 动作合成 standardMd 时遵循。
> 依据：REQ D6 + 需求方澄清（2026-09-18）：**以原始需求全文为底稿**，整合体检定论与澄清答复，产出完整可用的需求定稿。
> 一句话：把「原文快照 + 体检定论 + 澄清答复」整合成一份**开发可直接开工、AI 可独立读懂**的需求文档。
> 正文中的原文出处（`详述N(.N)*` / 「详述6·步骤一」式）会由平台自动链接化——点击按块锚直达原文条款（无 doc 数据时回退文本定位）。合成时**保留出处原样**即可，无需改写格式。
> 澄清答复输入一律取 `answerText`（平台解构后的纯文本——`answer` 原文可能是 `{"kind":...}` 结构化 JSON 串，直接消费会把裸 JSON 写进定稿）；已答结论固化的条款尾部带〔Pxx〕尾缀；挂起项（status=deferred）以〔Pxx·挂起〕标注。

## 0. 目标（验收口径）

1. **开发可用**：拿到这一份文档即可开工，不需要回飞书原文，不需要翻 31 条澄清记录对照。
2. **AI 可读**：AI 只读这一份文档即可获得——
   - **全貌**：功能模块与业务规则全集（原文规则的完整承载，不是摘要）；
   - **边界**：本期范围、明确不做、角色权限边界、遗留假设口径；
   - **逻辑**：状态机流转、字段×状态矩阵、校验链、时间依赖等，以结构化文本表达、可被程序解析。
3. **可追溯**：每处整合有 ✅/⚠️ 标注与引用记号，裁决过程保留在附录。

## 1. 底稿与输入

| 材料 | 用途 |
|---|---|
| **原文快照**（push 时 lark-cli 拉取的飞书全文） | **底稿**。正文的规则全集必须等价覆盖原文，不得因"整合"丢内容、丢细节、丢例外条款 |
| digest（FR 注册表/功能地图/假设清单） | 章节组织索引 + 假设口径来源；骨架是索引，**不是内容上限** |
| audit（问题明细 + go 定论） | go=✅已确认 的定论合入正文；go=跳过 不改正文 |
| 澄清清单 + 平台已答复（pull-answers 后） | 逐条消化的主要输入 |
| cases.md（可选） | 仅用于核对术语与编号，不改变需求内容 |

## 2. 文档结构

```
# <需求名> · 标准需求文档（定稿）
元信息头（两列表格 5 行，模板见结构图下方，逐字照抄形态）

一、需求概述与边界
   1.1 概述（原文简述 + 本轮范围变化）
   1.2 本期范围 / 明确不做          ← 边界
   1.3 术语表（体检定论统一后的命名）  ← 逻辑/全貌
   1.4 角色与职责（含权限边界）

二~N、按业务域组织的定稿正文          ← 全貌 + 逻辑的主体
   （以原文章节结构为基础逐域整合；每域内：）
   - 规则正文：原文规则 + 已答复结论合入（✅ 标注 seq）
   - 废弃条款：~~删除线~~ + 定案说明（如"总则句废弃，以 需求.FR-32 为准"）
   - 未答复/字面待复核：按假设口径行文，⚠️ 标注
   - 逻辑载体文本化：状态机流转表、字段×状态矩阵、校验规则（阈值/枚举/依赖）、时序约束

N+1、遗留假设汇总（需求.Axx，⚠️）     ← 边界的兜底清单
N+2、附录 A · 澄清结论表              ← 裁决记录，全文引用的落点
N+3、附录 B · 章节编号与引用修正（有此类修正时）
N+4、附录 C · 废弃条款清单（有废弃条款时）
```

**附录体系**（章标题须含「附录 A」「附录 B」「附录 C」字样——机检脚本按此定位表体，标题只写「附录：澄清结论表」而无 A 字样会触发 WARN）：

| 附录 | 内容 | 必要性 | 表列 |
|---|---|---|---|
| A | 澄清结论表（裁决记录） | **必须** | Seq｜级别｜主题｜问题｜结论｜影响章节｜状态 |
| B | 章节编号与引用修正 | 有此类修正时 | 原文标题｜原文问题｜定稿处置 |
| C | 废弃条款清单 | 有废弃条款时 | 序｜原文位置｜被废弃表述｜替代规则｜来源 |

- 附录 A 结论列取 `answerText`；挂起项结论列只写「待定 + 确认时机」（规则 7），状态列与对应假设行以〔Pxx·挂起〕标注
- 附录按 A→B→C 顺序排在遗留假设章之后；无对应内容时该附录整章省略
- **自查结论不进定稿**：机检输出与人工档结论在发布确认时向用户呈现，不落盘为文档章节

**元信息头模板**（紧跟 h1；两列表格固定 5 行不增删，值内不加统计类括注——块数/媒体数等细节不进头部；迭代不进头部，页面上下文已可见）：

```
| 项 | 内容 |
|---|---|
| 需求编号 | REQ-YYYY-NNN |
| 风险分级 | A（N 角色 × N 区块 × N 场景，跨 N 个业务模块） |
| 版本依据 | 原文 vX.Y.Z（YYYY/MM/DD）· 质检快照 YYYY-MM-DD · 合成 YYYY-MM-DD |
| 澄清进度 | n/N 已答复（固化 n，挂起 n〔Pxx·挂起〕；无挂起则省略挂起段） |
| 废弃条款 | N 处（正文删除线标注）
```

头部止于表格：**不在文档任何位置写符号/引用记号的语义说明**——记号含义是平台级通用约定，由平台 UI（标准需求文档页 banner 的「记号」浮层）承载；写进文档只是复读通用约定、占用读者注意。

全文保留引用记号：`需求.FR-xx`、`体检.Pxx`、`需求.Axx`、裸 `Pxx`——平台渲染时自动链接化（D7）。

## 3. 消化规则

1. **逐条消解（答复输入取 answerText）**：每条已答复澄清 → 定位原文对应规则位置 → 把结论合入正文 → 标 `✅（Pxx）`；结论影响多处时处处标注。**答复一律取平台出参 `answerText`**（`answer` 原文可能是 `{"kind":...}` 结构化 JSON 串——它是作答数据的存储形态，不是展示文本，直接消费会把裸 JSON 写进定稿）。固化条款尾部带〔Pxx〕尾缀（如「……全员可见。〔P03〕」，两位补零），与 ✅ 标注并用不冲突。**记号语义**：〔Pxx〕= 该条款口径由 Pxx 的 answerText 直接决定——按"答案决定"挂，不按"主题相近"挂；口径的真实来源是评论的标（评论 cN），不得错挂 P 号（错挂会把交叉追溯引向无关问答）。
1a. **来源分级（不发明的判定口径）**：合成采信的每条实质内容——字段名、角色名、枚举成员、权限归属——必须有可指认的来源（原文文本 / 评论 / 某条答复）。**来源仅为截图、原型或外链的条款，不得写入规则列**（与"截图不作验收依据"的口径自洽）：要么标〔截图来源·待确认〕，要么转入遗留假设；正文中凡依据截图内容行文的字段名/枚举，视为无源，按此处理。
1b. **权限禁类推**：某动作的权限无来源时，禁止从相近动作类推填位（"查看报告"的权限不自动适用于"发送/重新生成报告"）——留 ⚠️ 待 PM 确认或转遗留假设；权限矩阵的动作行集必须与正文各操作表的权限列做闭包核对，自称「N 类动作」时矩阵行数必须一致。
2. **冲突裁决**：结论与原文冲突时以结论为准，原文表述按废弃条款处理（删除线 + 说明），不并排保留两版。
3. **🤔 清零**：原文与 digest 中一切 🤔/待定记号必须消解——含 §5 流程图节点 🤔 与 §6 流转边表 `?` 行所列断点——定案（✅）或转假设（⚠️ + 需求.Axx）二选一，不得残留。
4. **不发明需求**：合成只整合、不新增。合成过程中发现的真空白（含边表 `?` 行断点澄清后仍未定案的）→ 写入遗留假设并标注，不得静默替需求方决策。
5. **跳过项**：audit go=跳过 的问题不改动正文；若其内容已按假设行文，在遗留假设中体现。
6. **原文优先保真**：原文的具体数值、枚举、例外条件一个都不能丢；结论只改变"被裁决的那一处"。
7. **挂起项〔Pxx·挂起〕**：status=deferred 的问题记入遗留假设（需求.Axx），假设行与澄清结论表均以〔Pxx·挂起〕标注来源——区分「已定案固化的〔Pxx〕」与「悬而未决的挂起」，后续轮次消化时可按标注回收。**挂起项不预答**：其口径列只写「待定 + 确认时机（如开发前/评审时）」，不得给出默认执行方向——"开发时确认"的裁决语义是悬置，不是授权合成方选边；假设清单声明"按同一口径执行"更放大了预答的危害。
8. **同一行为多处一致**：同一行为/规则在正文出现 ≥2 处时，各处表述逐字一致或显式互引（如「同 §3.6」）；澄清回写消歧后做一次全文名同实异的扫尾——同一动作的两处同义不同词（"置灰不可点"vs"可点后提示刷新"）就是留给下游的两读。

## 4. 质量自查清单（合成后先跑机检、再过人工档，才给用户过目）

自查分两档。**机检档由脚本执行**（`python3 scripts/check_standard_doc.py --doc <标准文档.md> --answers <answers.json> [--json]`，纯标准库；answers = publish 时 `GET /api/requirements/<reqId>/answers` 落盘的临时 json——pull-answers 的落盘产物是 markdown 清单，机检不消费；缺失时跳过依赖项并提示）——声明式自查不可信，凡能程序判定的不得靠自述。**人工档**逐项过，检查方法随项给出。

**机检档（脚本输出 FAIL 必须处理后重跑；WARN 需人工裁决；括号内为脚本项名锚）**：

- [ ] 附录澄清结论表的结论列与 answers 的 answerText 逐条一致（`qa-compare`；需 --answers，无输入时改人工抽查附录 ≥5 条）
- [ ] FR 编号连续无断号、无引用不存在的 FR 号（`fr-continuity`）
- [ ] 澄清 P 号：附录登记的每条在正文有落点（〔Pxx〕/裸 Pxx），正文无越界幽灵 P 号（`p-coverage`）
- [ ] 遗留假设 A 系列：声明章内 Axx 与正文引用 Axx 双向一致（无幽灵引用、无声明未引用需逐条确认是否如"不进正文"类故意）（`a-registry`）
- [ ] 正文删除线片段数与附录 C 废弃条目登记数吻合（数量级偏离即排查漏登记）（`strike-vs-appendixc`）
- [ ] 计数断言一致：「N 段/N 项/N 类/N 条」等显式计数与其后最近列表/表体条目数相符（`count-assert`，WARN 级）
- [ ] 矩阵自称动作数与矩阵实际行数一致（如「8 类动作」vs 表行数）（`matrix-assert`）
- [ ] 正文与澄清结论表零裸 JSON：不含 `{"kind":` 字样（答复全部取自 answerText——出现即输入口径违规）（`raw-json`）
- [ ] 元信息头按模板：紧跟 h1 两列表格固定 5 行、键序一致，值内无统计类括注，全文无记号语义说明（`meta-header`；「版本依据」缺原文/快照/合成时间锚为 WARN）
- [ ] 记号语义抽查：〔Pxx〕处条款与该 P 的 answerText 关键词重叠度过低时提示"疑似按主题相近错挂"（`p-semantic`，WARN 级，需 --answers）
- [ ] 「本期不做/⛔」正文章节字符占比 ≤5%（`scope-discipline`，WARN 级；范围外内容以整章留档即超阈值）
- [ ] 自包含声明与正文一致：声明「自包含/不依赖任何外部」后，正文不得出现「以原型为准/以页面示例为基准/详见附件/见飞书原文」等依赖表述（「原型…报废/废弃」反向语境豁免）（`self-contained`；未声明时不检查）
- [ ] 失败态可测：状态机边「→ X失败」所在小节须有判定条件关键词（超时/错误码/重试/判定/阈值/降级），否则该失败态无触发条件（`failure-trigger`；无状态机失败边时不检查）
- [ ] 挂起项投影：status=deferred 的澄清项须在正文有〔Pxx·挂起〕标注或遗留假设章登记——「挂起→遗留假设」不能只停留在发布记录层（`deferred-link`，WARN 级，需 --answers）

**人工档**：

- [ ] 原文快照的每条规则都能在文档中找到落点（对照快照逐节扫一遍）——全貌
- [ ] 本期范围 / 明确不做与 digest 一致——边界
- [ ] 状态机、矩阵、校验链、时间依赖在正文中完整且自洽——逻辑；**枚举闭包**：状态机出现的每个状态在"程序可解析"速查表必有一行，多张枚举表之间粒度一致
- [ ] 权限矩阵动作行集与正文各操作表的权限列闭包一致（哪些动作入矩阵、漏行即补；矩阵与正文互相脱节是高频缺陷）
- [ ] 全部澄清问题有着落：正文 ✅ 或附录裁决记录可查
- [ ] 🤔 清零（含 digest §5 图节点 🤔 与 §6 边表 ? 行）；⚠️ 仅限真实未定案/字面待复核项，且汇总在遗留假设
- [ ] 来源分级（规则 1a）：字段名/角色名/枚举成员逐个问来源——截图来源的条款不在规则列
- [ ] 挂起项不预答（规则 7）：每条挂起的口径列只有"待定+确认时机"
- [ ] 同一行为多处一致（规则 8）：抽查高频动作（生成/删除/导出类）在正文各处表述
- [ ] 通读无"见飞书原文 / 见原型 / 详见附件"类外指依赖（自包含）
- [ ] 挂起项全部在遗留假设且带〔Pxx·挂起〕标注；已固化结论带〔Pxx〕尾缀
