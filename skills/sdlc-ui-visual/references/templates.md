# 模板：run.md 与最终汇报

> 两份模板：run.md 是全程唯一状态源（创建即落盘、每步更新）；汇报是步骤 7 的最终产物。不引用其他 references。

## A. run.md 模板（`.ui-check/<目标名>/run.md`）

```markdown
# UI 视觉还原台账：<目标名>

## 进度
- [ ] 步骤 0 环境与可达性
- [ ] 步骤 1 基准获取（expected.md 已建，小元素⚠ 已打标）
- [ ] 步骤 2 代码对照（git diff 盘点 + 对抗清单）
- [ ] 步骤 3 稳定化 + 首轮截图
- [ ] 步骤 4 多道比对（r1）
- [ ] 步骤 5 差异分类 + 修复轮（当前 r_）
- [ ] 步骤 6 功能回归
- [ ] 步骤 7 汇报

## 基准信息
- 来源：<Figma fileKey/nodeId 或本地基准图路径>
- frame 选择：<整页 node-id + 主内容区 frame 及选择理由 / 组件级直用 node-id>
```

## B. 汇报模板（步骤 7 产出，`.ui-check/<目标名>/report.md`）

> 硬性要求（可审计性）：比对产物路径与 compare.py 统计数字（各轮 mean diff / >30 占比）必须原样引用出现在第 2 节；存在未执行或降级的验证项时必须单列在第 5 节「未验证项」，无则写「无」——这是「不得假称完成比对」红线的落点。

```markdown
# 视觉还原汇报：<目标名>

## 1. 修改文件及原因
| 文件 | 改动 | 级别（P0/P1/P2） |
|---|---|---|

## 2. 比对轮次与数据
轮次数、每轮 mean diff / >30 占比（引用 stats.txt 原值）、关键热区前后对比、DOM 实测尺寸前后对比、产物文件路径

## 3. 修复前后改善（可量化）
如：栏宽 342→300（=设计稿）、横向溢出 38→0、图标区域热区 6+→2、图标墨迹 29%→100%

## 4. 产物位置
基准图 / 各轮截图 / overlay / diff / 局部对比 / 回归截图 所在目录

## 5. 检查结果与未验证项
交互断言逐项 / 同页其他 Tab 回归 / 共用组件调用方回归（产物在本目录 regression/）/ lint / console 归因 / 编译产物
**未验证项**（未执行/降级的验证，逐条列明原因与影响；无则写「无」）

## 6. 保留的偏差
| 偏差 | 原因（分类） | 是否需人工确认 |
|---|---|---|
```
