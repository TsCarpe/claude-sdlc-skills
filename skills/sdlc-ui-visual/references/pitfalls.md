# 坑速查（栈无关）

> 现象 → 根因 → 解法触发表。组件库特有坑不在本页（见栈绑定文件）。不引用其他 references。

## 环境/工具坑

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | 设计数据 MCP 输出超大被截断 | 上下文上限 | 持久化到本地 json/txt 再分段分析 |
| 2 | DOM 查询/a11y 树为空，但截图有内容 | 页面弹窗干扰 + 截图为旧帧 | 先关弹窗 + 轮询主内容挂载 + 挂载后再截 |
| 3 | 浏览器页面莫名被关闭/刷新 | 弹窗逻辑刷新页面 | 操作前状态存 localStorage，失败重开恢复 |
| 4 | 用户反馈与本地渲染不一致 | 用户浏览器缓存混搭（新 DOM + 旧 CSS） | 建议硬刷新；以本地 dev 实测为准 |
| 5 | 用户截图无标注、描述模糊（「太靠左」） | — | PIL 逐行暗像素聚类分析其截图定位元素几何，再用选择题确认期望方向，避免改反 |
| 6 | 比对脚本崩（无 numpy） | 依赖缺失 | 纯 PIL 方案（ImageStat 替代 ndarray 统计） |
| 7 | 基准图与截图尺寸不一致就拉伸 | — | 禁止拉伸：先查视口/Frame 尺寸/设备像素比；基准 2x 等比（LANCZOS）缩到 1x |

## CSS 布局坑

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 8 | 元素视觉宽比 CSS 写的宽（342 vs 300） | `width` 是 content-box，padding+border 外加 | `box-sizing: border-box` |
| 9 | 改盒模型后子元素溢出 | 内联 `style="width:Npx"` 是旧口径遗留 | 内联固定宽改 `100%`；逐层排查固定宽（含带 `!important` 的） |
| 10 | 页面横向溢出、flex 子项超宽 | flex 子项默认 `min-width:auto` 被内容撑开 | 子项 `min-width: 0` |
| 11 | 容器比父内容区宽/顶边框 | 历史 hack `width: Npx !important` | 改 `auto` 自适应；外层用 `max-width:100%` 兜底 |
| 12 | 修完一处样式另一处错位 | 全局样式覆盖压制（未盘点对抗清单） | 动手前 grep 全局覆盖文件列对抗清单（SKILL.md 步骤 2） |

## 修复姿势

- 先修整体布局与父容器，再抠组件尺寸/间距/字体/颜色细节（P0>P1>P2）
- 用 Flexbox/Grid 表达设计稿的布局意图，不叠加 margin/硬编码坐标/绝对定位掩盖
- 共用组件只做增量：改前先想「这个 class 还有谁在用」，改后回归调用方页面
