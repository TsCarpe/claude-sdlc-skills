# 派发协议（exec 阶段子 agent 分批执行）

> 目的：四类证据底线不变，把大体积中间信息（DOM 快照/网络请求列表/截图/报文）隔离在子 agent 上下文，主上下文只收压缩结论——token 消耗与用例数量解耦。批间串行，共享同一浏览器/MySQL MCP 会话。

## 批派发规则

- 主 agent 每批取 **3-5 条用例**派给一个子 agent；「执行分组」G-xx 整组必须落入同一批，不得拆散
- **批间串行**：上一批回传并回填完成后才派下一批（共享浏览器会话 + cases.md 单写者，禁止并发派发）
- 批的切分顺序：重点验证项关联用例 → P0 → P1 → P2；同批尽量同页面/同模块，减少侦察重复
- **提交类断言单独成批、置于批末（红线）**：涉及提交/落库的用例（含组尾提交型，如 G-02 的 TC-27）不得混入拦截组中段——提交即关闭向导会话，混排会挤掉未完成的拦截断言、迫使整场基准重走（2026-09-13 R2 实测教训）。切批方式：先跑纯拦截组（全程不提交、取消退出、逐段落 exec-log 后），再开提交场；一场提交只承载一个提交目的（如"无专家配置落库探测"），提交场用例名称写明用途留痕
- 断点续跑语义不变：`--from TC-xx` 从该条起按序切批；中断恢复以 exec-log 最后一段的下一条为锚点重新切批

## 子 agent prompt 模板（自包含 + 最小挂载）

```
执行以下测试用例批次，本轮目录：<sdlc/<需求名>/test/reports/<日期>-r<N>/

【批内用例】（从 cases.md 原文拷贝用例条目：新格式=TC 小节全文，存量表格文件=表格行原文；含步骤/预期/关联规则/重点验证项关联）
TC-xx：…

【环境】读 sdlc/env/test.md 与 accounts.local.md 登录；ui-recipe：sdlc/env/ui-recipe.md（含路由与鉴权头）
【姿势】浏览器/数据库操作姿势手册：<逐条挂载本批涉及的 references/exec/exec-interaction.md 条目，含 MySQL 断言规范与证据采集节>
【判定规则】
- 执行≠验证；操作后 wait_for 等稳定再取证
- 每条用例四类证据齐全：页面表现 + 接口响应 + 落库核验 + console（error 必查）；缺一标"疑似"
- 判"通过"前查看全页截图复核视觉
- 口径冲突三去向：实现偏离=BUG-xx / 需求未定=转 Q / 用例写错=修用例；禁止静默按实现校正预期
- 造数走前端页面操作，禁改库；MySQL 只读
- 反合理化表：（SKILL.md 原文拷贝）
【失败处置】姿势失效按 references/exec/exec-interaction.md 三类归因；疑似偶发/环境性失败（复跑结果不一致、网络超时、非确定性报错）单条重跑一次（retry-once），两次一致才定论
【留档】每条用例执行完立即向 exec-log.md 追加一段，并同步更新该文件「结果总览」表中本用例行的结果/截图单元格（格式见 references/exec/exec-log-template.md 单用例段：结果/证据按页面-接口-落库-console 四类分行/复现锚点/备注；通过的 P0/P1/BUG 关联用例必须写复现锚点——语义选择器/接口 URL/业务键），截图落本轮 screenshots/
【回传】最终只回传每用例一行的压缩结论（见回传协议），不要回传截图、网络报文、快照原文或完整执行过程
```

- **最小挂载**：只放本批用例涉及的姿势条目与规则（如批内无上传则不带 el-upload 行；无落库断言则 MySQL 节可省）；侦察发现需要未挂载姿势时按手册维护规则试错并回写，不为省 token 砍证据
- 红线（四类证据/造数/口径冲突/反合理化）**原文携带**，不因派发压缩而放松

## 回传协议（每用例一行）

```text
P0: TC-07 | 失败(R1)→BUG-01 | 证据: TC-07-01.png;POST /v1/xx code=1001;快照行数1≠3 | 拍板口径 D-01 落改，实现只传1个合作方
TC-03 | 通过(R1) | 证据: TC-03-01.png;POST /v1/xx code=0;count=1 | —
TC-04 | 疑似(R1) | 证据: TC-04-01.png;—;— | console error 无法解释，已留痕
```

- 字段：`TC-xx | 结果(R<N>) | 证据: 截图名;接口;SQL摘引 | BUG-xx? | 备注≤2句`；P0 缺陷行置顶并加 `P0:` 前缀
- BUG 编号由子 agent 按本轮已有序号顺延登记（先读 exec-log/cases 现有最大号），避免主 agent 二次分配
- **禁止出现在回传里**：截图、网络报文原文、DOM/快照原文、完整操作步骤叙事——这些只落盘（exec-log/screenshots）

## 主 agent 职责（每批之间）

1. 派发前：确定本轮目录与用例范围，切批，从 cases.md 拷贝批内用例条目原文（新格式=TC 小节，存量表格=表格行）组装 prompt
2. 回传后：按结论回填 cases.md（结果字段、证据摘要、缺陷跟踪表、头部进度——新格式：总览表结果列与 TC 小节证据行；存量表格：结果列与证据列）——纯文本操作
3. P0 结论立即向用户转述快报（自解释措辞），不等整批跑完
4. 判定是否继续下一批：连续阻塞（环境失效/登录态崩）时停止并报告，不空转派发

## anti-flake（失败处置）

- 失败先按 references/exec/exec-interaction.md「失败归因」三分类排查姿势/等待问题，姿势修正后重试不算 retry
- 疑似偶发/环境性失败（同操作两次结果不一致、网络超时、非确定性报错、data race 特征）：**单条重跑一次（retry-once）**，两次一致才定论；不一致时以两次观察留档，标 `flake疑似`，不登记 BUG，转重点观察
- retry-once 上限 1 次/用例/轮：重复偶发本身是证据，写入备注交人工判断，不无限重试
