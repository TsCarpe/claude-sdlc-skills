# 用例文件模板

产出路径：`sdlc/<需求名>/test/cases.md`。严格按此结构（ALWAYS use this exact template）。模板区块顺序：头部元数据 → 设计技术覆盖矩阵 → 双向追踪表 → 重点验证项 → 执行分组 → 用例总览（状态唯一权威）→ 用例明细 → 缺陷跟踪；字段口径与存量兼容见文末：

## 目录

> 本目录是 case-template.md 自身的导航（本文 >100 行，供部分读取时预览范围），非产物内容；产出的 cases.md 只含下方 fenced 模板主体，不含此目录。

- 模板主体（上方区块顺序，fenced 全文照抄）
- [字段口径](#字段口径)
- [存量表格文件兼容](#存量表格文件兼容)

## 字段口径

- **ID**：TC-01 起连续编号，新增不重排（断点续跑依赖编号稳定）
- **结果**：只写在「用例总览」结果列，格式 `通过（R<N>）` / `失败（R<N>）` / `阻塞（R<N>）` / `疑似（R<N>）`，未执行留空——只反映**最新执行轮次**，历史判定在各轮 exec-log 留档（sdlc/<需求名>/test/reports/<日期>-r<N>/）；回填**不带状态图标**（图标仅用于 exec-log）
- **证据**：TC 小节「证据」行，执行后回填一行摘要——截图文件名（`screenshots/TC-01-01.png`）+ 接口 + SQL 摘引；完整过程证据见当轮 exec-log
- **角色/状态名**：沿用梳理文档口径，不自造同义词

## 存量表格文件兼容

存量 cases.md 若为旧版 10 列明细巨表（结果/证据为列），**不必重排**：结果/证据/手标/`spec ✓` 一律就地按原列维护，上文字段口径同样适用（「用例总览列」↔「表格结果列」等价）。
