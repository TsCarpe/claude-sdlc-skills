# 冒烟清单模板（sdlc/<需求名>/dev/smoke.md）

由 `/sdlc-test dev` 第①步从 cases.md 的 P0/核心链路用例推导生成（计划-验证-执行：verify_dev.py 先校验本文件结构再执行）；生成后人工可增删，头部责任字段必填。断言只有四种确定性 DSL——复杂业务断言（落库/权限）不写本文件，留 exec 阶段四类证据。

## 条目结构

```markdown
# <需求名> 冒烟清单

| 项 | 值 |
|---|---|
| 来源 | sdlc/<需求名>/test/cases.md |
| 生成日期 | YYYY-MM-DD |
| 生成会话 | <会话/agent 标识> |
| 复核人 | <姓名> |
| 不适用 P0 | <TC-xx：<一句话原因>；全部适用写「无」> |

## SM-01 创建作品
- 请求: POST /api/works
- 请求体: {"title": "冒烟测试作品"}
- 预期: HTTP 200 且 code=0 且 存 id ← data.id
- 来源: 用例.TC-01

## SM-02 查询作品
- 请求: GET /api/works/{{id}}
- 预期: HTTP 200 且 code=0 且 包含"冒烟测试作品"
- 来源: 用例.TC-02
```

## 填写规则

| 项 | 规则 |
|---|---|
| 请求 | `METHOD /path`——path 相对 env/dev.md「冒烟/base URL」；支持 `{{变量}}` 插值（引用前条「存」下的变量） |
| 请求体 | 单行 JSON，支持 `{{变量}}` 插值；POST/PUT/PATCH 才发送。**插值需自行包裹引号**（`"refId": "{{id}}"`——值以字符串原样替换，不做 JSON 转义）；值含引号/特殊字符时不宜用于请求体插值 |
| 预期 | 四种断言以「且」连接：`HTTP <n>`（状态码）/ `code=<n>`（响应 JSON 顶层 code）/ `包含"<文本>"`（响应体子串）/ `存 <变量> ← <点路径>`（如 `data.id`，提取变量供后续条目插值）；其余写法解析即拒 |
| 来源 | `用例.TC-xx`——须为 cases.md 中存在的用例（脚本核对） |
| 条目顺序 | 按文件序执行，前条数据后条可用（创建→查询链）；单条失败不中断后续，全量留档 |
| 鉴权文件注释 | dev-auth.local.md 逐行按「头名: 值」解析、**不识别 # 注释**——注释行含 `：`/`:` 会被当鉴权头送出（非 ASCII 头值直接报错），注释勿单独成行 |
| 断言文本 | `包含"<文本>"` 的文本勿含引号字符（`"` `“` `”` 是 DSL 分隔符，写入即在引号处截断）；需断文案时改用无引号特征子串或业务键 |
| 真实实参 | 请求体/URL 勿用假 id 占位（如 `"1"`）——业务前置校验（存在性等）会先于目标逻辑拦截；生成清单时即取真实 id（查库只读 / 问用户 / har 抓包） |
| 断言防呆 | 「包含」勿选 data/status 等通用键名——错误响应体同样含这些键（实测假阳性教训）；选仅成功响应才有的业务键（如名称、业务编码） |
| 不适用 P0 | 每个 P0 用例要么有条目、要么在头部「不适用 P0」逐条列原因——防静默缩面 |
| 禁写内容 | 鉴权真值（引用 sdlc/env/dev-auth.local.md）、内网域名/真实项目名（脱敏红线） |
