# 用例文件模板

产出路径：`sdlc/<需求名>/test/cases.md`。严格按此结构（ALWAYS use this exact template）：

```markdown
# <需求名> 测试用例

> 需求来源：sdlc/<需求名>/intake/digest-<日期>.md（及体检/PM 清单）
> 生成日期：YYYY-MM-DD
> ID 体系：本文件产出 用例.TC-xx、缺陷.BUG-xx；引用他产物条目须带命名空间（需求.FR-03 / 体检.P04 / 设计.D11）

## 头部元数据

- 审核状态：草稿 | 已确认（YYYY-MM-DD）
- 阶段进度：
  - [ ] 阶段1 用例生成
  - [ ] 🔒 关卡1 用例审核
  - [ ] 阶段2 静态代码检测
  - [ ] 阶段3 前端功能测试（进度：0/N）
  - [ ] 阶段4 报告生成
  - [ ] 🔒 关卡2 报告复验

## 设计技术覆盖矩阵

| 技术 | 适用规则/字段数 | 已覆盖 | 用例 ID |
|---|---|---|---|
| 等价类 | n | n | TC-01,TC-03… |
| … | | | |

（逐技术填写；未适用必须写原因，不许静默跳过）

## 双向追踪表

| 条目（需求.FR-xx） | 来源（章节） | 覆盖用例 ID | 未覆盖原因 |
|---|---|---|---|
| 需求.FR-01 … | §7 关键规则 | TC-12 | — |
| §6 状态机 S2→S3 边 | §6 状态机 | TC-15 | — |
| … | | （空） | 待PM澄清边界值 |

（未覆盖条目必须列原因；行主键优先用 需求.FR-xx，FR 之外的来源写章节，禁止自造 R1 类规则编号）

## 重点验证项

（体检报告疑似问题 + 静态检测 ⚠️ 疑似偏差，逐条列出并关联用例 ID；阶段2 之前为空。引用格式：体检.P04 / 静态.01）

## 执行分组（可选，生成时标注）

（同基准流的拦截类用例标为一组，exec 阶段同一表单会话内连续验证、每条断言后复原；**涉及提交/落库的用例不入组**。存量用例可在 exec 前补本区块，不必重新生成）

- G-01｜共享基准流：<如"进入创建向导填合法基准值到步骤N">｜成员：TC-03,TC-04,…｜复原策略：<如"每条断言后复原该字段">

## 用例明细

| ID | 优先级 | 设计技术 | 前置条件 | 角色 | 步骤 | 预期（页面/接口/落库） | 关联规则 | 结果 | 证据 |
|---|---|---|---|---|---|---|---|---|---|
| TC-01 | P0 | 场景法-基本流 | 已登录管理员 | 管理员 | 1.进入xx页 2.填写… 3.提交 | 页面：列表新增一行；接口：POST /v1/xx 返回 code=0；落库：xx 表新增记录 status=1 | 需求.FR-01 | （留空） | （留空） |

## 缺陷跟踪（执行时维护）

（用例文件是缺陷生命周期唯一权威：新失败登记，回归通过闭环；各轮 report 摘引当轮切片）

| 缺陷ID | 端 | 关联用例 | 描述 | 发现轮次 | 状态 | 修复轮次 | 备注 |
|---|---|---|---|---|---|---|---|
| BUG-01 | 前端 | TC-07 | （一句话现象+与预期的差异） | R1 | 待修复 | — | 非缺陷时标「已关闭」并写原因 |

端判定口径：**前端**（页面交互/展示/输入校验）/ **后端**（接口校验/落库/业务规则）/ **前后端**（链路两端均有责任，描述里分别写明两端行为）/ **待定**（备注写待查方向）。

状态口径：待修复 / 已修复（回归轮重跑通过）/ 已关闭（判定为非缺陷/按实现口径接受）/ 暂缓。
```

## 字段口径

- **ID**：TC-01 起连续编号，新增不重排（断点续跑依赖编号稳定）
- **结果**：`通过（R<N>）` / `失败（R<N>）` / `阻塞（R<N>）` / 未执行——只反映**最新执行轮次**，历史判定在各轮 exec-log 留档（sdlc/<需求名>/test/reports/<日期>-r<N>/）
- **证据**：截图文件名（`screenshots/TC-01-01.png`）+ 接口 + SQL 摘引，逗号分隔；完整过程证据见当轮 exec-log
- **角色/状态名**：沿用梳理文档口径，不自造同义词
