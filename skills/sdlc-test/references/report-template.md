# 测试报告模板

产出路径：`sdlc/<需求名>/test/reports/<日期>-r<N>/report.md`（与同轮 static.md / exec-log.md / screenshots/ 同目录）。严格按此结构：

```markdown
# <需求名> 测试报告 R<N>

> 日期：YYYY-MM-DD　环境：test（<URL>）　分支/版本：<git branch / 版本号>
> 用例：N 条（P0 n / P1 n / P2 n）　来源：sdlc/<需求名>/test/cases.md
> 轮次：R<N>（R1 全量 ｜ R<N> 回归：重跑范围 TC-xx,…；上轮报告见 ../<日期>-r<N-1>/report.md）

## 1. 执行摘要

（一段话：本轮通过 x / 失败 y / 阻塞 z；缺陷闭环 a / 新增 b / 遗留 c；结论建议：可提测上线 / 修复后回归 / 阻塞中。最严重的 1-3 个问题一句话点出）

## 2. 结果统计

| 维度 | R<N> 本轮 | 累计（用例文件最新状态） |
|---|---|---|
| 通过 | n | n |
| 失败 | n | n |
| 阻塞 | n | n |
| 未执行（含原因） | n | n |

## 3. 静态检测发现

（摘引同轮 static.md：⚠️ 疑似偏差逐条 + 动态验证结果——静态疑似在动态被证实/证伪。回归轮只列复检项）

## 4. 功能测试结果

按优先级列出本轮失败/阻塞用例（通过的只给统计不展开，详见用例文件与同轮 exec-log.md）。

## 5. 缺陷清单（本轮切片）

摘引用例文件「缺陷跟踪」表当轮相关行，补全四要素：

| # | 用例 | 严重度 | 预期 | 实际 | 复现步骤 | 疑似代码位置 | 证据 | 状态 |
|---|---|---|---|---|---|---|---|---|
| BUG-1 | TC-07 | 高 | … | … | … | OrderServiceImpl.java:120 | TC-07-01.png | 待修复 |

严重度口径：高（主流程不可用/数据错误）/ 中（功能缺陷有绕行）/ 低（体验/展示）。
回归轮：新增缺陷全列；已闭环缺陷只列闭环情况（BUG-xx：R<N> 重跑通过）。

## 6. 覆盖度

- 用例执行覆盖：本轮 x / 范围内 N；全量用例累计 y/总数
- 规则条目追踪：覆盖 m / 未覆盖 k（未覆盖条目及原因，摘引双向追踪表）
- 证据降级说明：哪些用例只拿了截图证据（a11y 失明降级）

## 7. 遗留与建议

（未验证项、环境限制、建议人工补充的探索性测试点）
```

## 纪律

- 缺陷生命周期唯一权威在用例文件「缺陷跟踪」表；本报告只做当轮切片，不复写状态
- 缺陷**不自动推送**任何外部系统；关卡2 由用户复验真伪后自行转达开发
- 每条新增缺陷必须有四要素：预期 / 实际 / 复现步骤 / 证据（截图或接口响应或 SQL 结果）
- 静态 ⚠️ 与动态结果要闭环对照，防止静态误报直接进缺陷清单
