> 方法：需求规则逐条比对实现链路（Controller → Business/Service → Mapper/XML），前端按权限投影/校验函数/交互组件检视。仓库配置见 sdlc/env/repos.local.md

## 统计

### 口径一：按比对清单行数（共 n 行）

| 结论 | 行数 | 明细 |
|---|---|---|
| ✅ 符合 | n | （含 x 行主结论 ✅ 但附带交叉引用的疑似偏差：需求.FR-xx→静态-0x） |
| ⚠️ 疑似偏差 | n | 需求.FR-xx…（行结论引用了静态-0x 的行） |
| ❓ 静态无法确认 | n | 需求.FR-xx… |

### 口径二：按独立问题条数（去重同源，标注端别）

| 类别 | 端 | 条数 | 问题 |
|---|---|---|---|
| ⚠️ 疑似偏差 | 前端 | n | 静态-0x… |

> ⚠️ n 条已全部同步至用例文件「重点验证项」；❓ n 条均已关联功能测试用例。

## 口径

- **结论只有三态**：✅符合 / ⚠️疑似偏差 / ❓静态无法确认；静态阶段不下"缺陷"定论，疑似偏差一律交阶段3 动态验证
- 代码位置必须精确到 `文件:行号`（用 CodeGraph 定位后 Read 确认），前后端位置分别标注仓库
- ❓ 的典型来源：定时任务、异步消息、前端交互细节、第三方回调、数据中台口径
- ⚠️ 若涉及资损/数据不可逆等重大风险，不等阶段3，立即单独报告用户
- 回归轮（r2+）只复检上轮 ⚠️/❓ 项与本轮代码变更涉及规则，留档注明复检范围；上轮 ✅ 项默认仍有效，`--all` 才全量重比

## 偏差编号与计数硬规则（防口径混乱）

- **偏差编号单一序列**：⚠️ 问题统一登记在「疑似偏差明细」表，只用 `静态-0x` 编号（每轮从 01 起）。比对清单行的结论列只**引用**偏差编号（如 `⚠️疑似偏差（静态-01）`），规则编号（需求.FR-xx）不得直接充当偏差结论载体——同一实现问题只编一个号，禁止「静态-0x 与 需求.FR-xx 同源各计一次」的重复计数
- **「端」列必填**：前端 / 后端 / 前后端，判定依据 = 问题代码位置所在仓库（拿不准时双仓库 grep 确认函数归属再定）
- **双口径计数，写完自查**：
  - 口径一数的是比对清单行，口径二数的是疑似偏差明细表行（❓ 项无独立偏差编号，按清单行引用计入）
  - 对外引用的统计数字以**口径二**为准；两口径数字必须能分别从比对清单、疑似偏差明细表逐行数出，写完逐行点数核对
  - 清单行结论与偏差明细交叉引用时，该行计入其主结论：✅ 行附带的 ⚠️ 引用在口径一「明细」列注明，不重复计入 ⚠️ 行数
