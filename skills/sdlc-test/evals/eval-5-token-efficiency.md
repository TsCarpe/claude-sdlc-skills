# eval-5：exec token 效率（派发隔离/最小挂载/retry-once/定向取证）

基线（待回填）：首批真实跑记录单批（5 条用例）主上下文新增 token；优化前单条用例全量证据+双写均在主上下文（社区同型实测单用例快照类消耗可达 ~114K token，定向化+隔离后预期降 60-80%）。

## 5a 派发合规（上下文隔离）

输入：exec 阶段 ≥2 批用例

- [ ] 主 agent 未在自身上下文逐用例操作浏览器（无逐条 take_snapshot/点击/证据采集）
- [ ] 子 agent 回传仅含每用例一行压缩结论（`TC-xx | 结果(R) | 证据 | BUG-xx? | 备注≤2句`）
- [ ] 回传中未出现截图、网络报文原文、DOM/快照原文或完整操作叙事
- [ ] 批间串行：上一批回填完成后才派下一批，无并发派发
- [ ] cases.md 回填（结果字段/缺陷跟踪表/头部进度）由主 agent 按回传结论完成

## 5b 红线携带（质量不因派发下降）

输入：任意一批含失败用例

- [ ] 子 agent prompt 原文携带四类证据规则、造数纪律、口径冲突三去向、反合理化表
- [ ] 每条用例四类证据齐全（页面/接口/落库/console），缺一标"疑似"，未因隔离放松
- [ ] exec-log.md 段落由子 agent 写入且每用例一段（判定+证据引用+备注）
- [ ] 口径冲突有三去向判定留档，无"静默按实现校正预期"
- [ ] P0 缺陷在回传中置顶（`P0:` 前缀）且主 agent 立即快报

## 5c 最小挂载

输入：批内用例不涉及上传/富文本等控件

- [ ] 子 agent prompt 未携带本批用不到的姿势条目/模板内容
- [ ] 红线与 MySQL 断言规范、失败归因始终携带（不属于可裁剪项）

## 5d 定向取证与 retry-once

输入：断言接口 URL 已知；批内含 1 条疑似偶发失败

- [ ] 接口证据优先 `get_network_request` 定向获取，无逐用例全量 `list_network_requests`（定位不到目标时使用除外）
- [ ] 等待稳定用 `wait_for`/网络完成确认，无轮询 take_snapshot
- [ ] 截图先落盘；主上下文未加载任何图片；展示类断言/异常疑点外不 Read 截图
- [ ] 疑似偶发失败 retry-once 恰好执行 1 次：两次一致才定论，不一致标 `flake疑似` 不登记 BUG
- [ ] 无无限重试（retry-once 上限 1 次/用例/轮）

红线：回传或主上下文出现截图/报文/快照原文、或四类证据因派发被裁剪 → 判失败。
