# 需求体检维度体系（六层）

> 体检阶段的检查锚点。每项含：命中定义（通用模式）与严重度倾向。维度是启发式锚点而非封闭清单——发现维度外的问题也应记录，维度标注为「补充」。
>
> **严重度定义**：
> - **阻断**：不澄清该问题无法产出技术设计
> - **严重**：不澄清会导致技术设计做错
> - **建议**：顺带确认即可，不阻塞设计

## 第 1 层 概念层

最先执行：先从原文提取术语表，后续所有层以该术语表为基准。

| 检查项 | 命中定义（通用模式） | 严重度倾向 |
|---|---|---|
| 概念缺失 | 某概念/模块/对象被流程、规则或字段引用，但全文无定义、无对应功能入口（如：规则引用了某个"库/池/中心"，但该对象的来源与管理功能无任何需求） | 阻断 |
| 概念冗余 | 术语释义表中定义的概念，正文无任何落点 | 建议 |
| 概念模糊 | 定义存在但不可操作或不可判定。典型模式：①"系统自动 X"但 X 的判定条件无法落地；②"尽量/合理/适度"等无量化口径；③判定主体未指明（谁来判断） | 严重 |
| 术语不一致 | 同一概念在不同章节使用不同名称（状态名、对象名、操作名的同义异名） | 严重 |
| 术语污染 | 与本需求业务域无关的词汇残留，疑似从其他需求文档复制 | 建议 |
| 概念混淆 | 两个相似概念边界未区分（如：发起人 vs 参与人、单个产物 vs 汇总产物、两类名称相近的对象），导致归属规则无法判定 | 严重 |

## 第 2 层 状态机与流程层

对原文中每个带状态的对象（单据、流程实例、生命周期实体）分别检查。

| 检查项 | 命中定义 | 严重度倾向 |
|---|---|---|
| 状态不闭环 | 某状态无进入路径或无出口；对象进入某中间态后去向未定义；缺少终态 | 阻断 |
| 触发缺失/歧义 | 三种模式：①流转依赖的操作在功能清单中不存在（无入口按钮/无角色负责）；②自动触发条件不可判定（如"全部完成时"未定义完成口径）；③触发依赖的参数无处配置（如依赖"期限"但配置流程无此字段） | 阻断 |
| 流转冲突 | 两处流转规则互斥（如一处写"单向不可回退"，另一处写"可撤销重做"） | 阻断 |
| CRUD 不闭环 | 对象只定义了新增/提交的正向流程，缺修改、删除、取消、停用等反向操作，或反向操作规则不完整（谁能做、什么状态下能做、做完数据去哪） | 严重 |
| 在途数据未处理 | 阶段切换、截止时刻、配置变更时，存量数据与进行中操作的处置未定义（典型：截止瞬间正在提交的数据、流程配置变更后已按旧流程走的数据） | 阻断 |
| 配置×状态交叉 | 存在可配置项（流程环节开关、模式选择等）时，配置的不同取值与状态分支/流程形态的组合未展开定义（典型：某环节可选，但删掉该环节后状态机的对应分支未说明） | 阻断 |

## 第 3 层 数据与字段层

| 检查项 | 命中定义 | 严重度倾向 |
|---|---|---|
| 引用不存在的字段 | 展示或规则引用了字段 F，但 F 的录入项在表单/配置流程中不存在 | 阻断 |
| 计算依赖缺失 | 计算公式的输入字段在需求中不存在（公式引用了无处填写的值） | 阻断 |
| 计算口径未定义 | 有数值结果但规则不明：多来源数值如何汇总（平均/求和/去极值）、换算关系、满分、精度、保留位数 | 阻断 |
| 约束不一致 | 同一字段在两处的必填性、类型、长度、取值范围互相矛盾（注意功能清单与表单详述两处） | 严重 |
| 单位/制式歧义 | 同一数值存在多种制式选项（百分比 vs 分制、天 vs 小时）但无默认值、无配置者 | 严重 |

## 第 4 层 规则与逻辑层

| 检查项 | 命中定义 | 严重度倾向 |
|---|---|---|
| 规则冲突 | 两处业务规则互斥（同一操作在两处的允许条件/结果不一致） | 阻断 |
| 规则依赖缺失 | 有时限/SLA/阈值约束，但超时、越限后的处理未定义 | 严重 |
| 权限口径缺失 | 数据可见性/可操作性未按角色定义，或某角色对关键数据的可见性未说明 | 严重 |
| 边界值未定 | 数量上限、次数限制等写了"可配置"但无默认值；或上限触发后的行为只提示不定义 | 严重 |
| 优先级规则缺失 | 并列、同分、同时刻的排序/取舍规则未定义 | 建议 |

---

## 第 5 层 角色与场景覆盖层

| 检查项 | 命中定义 | 严重度倾向 |
|---|---|---|
| 角色×功能缺口 | 某角色的功能只在清单/附录被提及，无详细需求（对照附录页面清单与正文详述逐项核对） | 阻断 |
| 清单-详述脱节 | 功能清单与详细描述条目对不上：清单有但详述缺失、详述有但清单缺失、两处同一条目的字段/操作不一致；序号断档 | 严重 |
| 通知矩阵缺失 | 状态变更、审核结果等事件×通知对象×通知渠道未系统化，仅零散提及"通知对方" | 建议 |
| 异常场景缺失 | 失败、超时、逾期、撤回、并发冲突等异常路径未覆盖（正向流程完备≠异常路径完备） | 严重 |
| 非功能性缺失 | 容量、性能、留痕、归档、审计等未提及（存在大文件上传、批量操作、外发内容时尤甚） | 建议 |
| 编辑影响未定义 | 声明某状态/阶段可编辑，但编辑对已产生数据（已流转记录、已计算结果）的影响未说明 | 严重 |

## 第 6 层 文档质量层

最后检查，多为低严重度，但删除不彻底与自相矛盾会实质性误导设计。

| 检查项 | 命中定义 | 严重度倾向 |
|---|---|---|
| 删除不彻底 | 某功能被标记删除/划线，但其他章节（清单、详述、状态流转、关键词表）仍引用——需确认该功能的最终去留 | 严重 |
| 自相矛盾段落 | 文档内两段陈述直接互斥（同一状态/操作两处描述相反） | 阻断 |
| 待确认与正文脱节 | 正文已写死规则，"待确认事项"中仍在问同一问题——以哪个为准 | 建议 |
| 外部依赖未附 | 原型/附件指向文档外部资源，评审时内容不可得 | 建议 |
| 编号低错 | 序号断档、空值单元格、格式残缺、修订记录与正文不匹配 | 建议 |
| 评论结论未同步正文 | 评论答复已形成结论/变更口径（梳理按评论提取），但正文对应章节未同步修订 | 建议 |

---

## 检查顺序与使用说明

1. **顺序固定**：1 概念 → 2 状态机与流程 → 3 数据与字段 → 4 规则与逻辑 → 5 角色与场景覆盖 → 6 文档质量。概念层的术语表是第 2、3 层的判定基准（术语不一致会放大为字段/状态矛盾）。
2. **逐层产出**：每层检查完记录命中项（维度/检查项/原文定位/引文），再进入下一层；层间发现新术语问题回写术语表。
3. **每条命中必须附原文定位**（章节或评论区 + 原句引用）。无法定位原文的猜测不写入报告。
4. **严重度从严**：拿不准标高一级，并在描述中说明不确定原因。
5. **去重合并**：同一根因在多层命中时合并为一条，维度标主责层，描述中提及关联层。
6. **严重度升级同步**：实际上下文允许偏离「严重度倾向」（如文档质量问题牵动状态机终态时上调），但**明细表的级别是唯一权威**——阻断速览的收录、第 1 章统计表计数、PM 清单分级计数必须全部与明细级一致。禁止「列入速览但明细级仍为原级」的中间态；速览只收明细级为 🔴 的条目。
