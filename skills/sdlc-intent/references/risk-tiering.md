# 需求风险分级评分卡（A/B/C）

> 术语映射：历史文档中的「重需求」≈ A 级、「轻需求」≈ B/C 级。
> tier 是产物头部字段，随 digest 头 → cases 头 → issues 头流动；下游环节（体检路由 / gate 分档 / 用例生成范围 / spec 资产化）只读字段，不回读本文档。
> 理论依据一行：DO-178C DAL / IEC 62304 Class A-C / ISTQB risk-based testing——按失败后果缩放验证深度；分级只裁机器工作量，不裁人工裁决权。

## 目录

1. 判定流程（谁判、何时拍板）
2. 影响面 6 项（判定特征与证据来源）
3. 需求级分级规则（A/B/C）
4. FR 级分级与聚合
5. tier 回写与上调通道（只升不降）
6. 存量回退与 guard 口径

## 1. 判定流程

- **时机**：梳理 Step 4（用户确认关卡）。AI 按本文评分卡给出 A/B/C 提议 + 命中依据（逐项列影响面命中情况），用户拍板后写入 digest 头部「风险分级」字段（确认改为日期）。
- **拿不准从高**：判 B 还是 C 拿不准 → 提议 B；判 A 还是 B 拿不准 → 提议 A。
- **降级需证据**：提议值低于影响面直观命中的，必须附可核对证据（如「原文明确本功能仅改前端文案，无后端改动」）；无证据不降。
- **为什么在梳理阶段拍板**：分级发生在写代码之前，不存在「想快点做完」的沉没成本；且分级影响后续所有环节的强度（体检路由、评审扇出、用例范围），必须最早定。

## 2. 影响面 6 项

| # | 影响面 | 判定特征（中性虚构例） | 证据来源 | 判定时机 |
|---|---|---|---|---|
| 1 | ER/表结构变更 | 出现新数据对象/新字段/存量表新增列（如「商品增加限购字段」） | PRD 原文、§3 核心概念、§7 规则表 | 梳理阶段可初判 |
| 2 | 数据迁移回填 | 涉及存量数据处理/历史数据补录/上线切换（如「存量订单需回填标记」） | PRD 原文 | 梳理阶段可判 |
| 3 | 公共组件 | 复用/修改既有共享组件或公共服务 | PRD 一般不写——**设计期确认** | 设计文档 / static |
| 4 | 对外契约（API 兼容） | 接口字段语义变更影响既有调用方 | PRD 一般不写——**设计期确认** | 设计文档 / gate |
| 5 | 资金/统计口径 | 计分、金额、报表、排名口径（如「总分=各评委均分去掉最高最低」） | §7 规则表分数/权重类条目 | 梳理阶段可判 |
| 6 | 并发一致性 | 锁、事务、幂等、竞态窗口（如「同一作品不可被并发评分」） | §7 规则表次数/上限类条目可判部分 | 梳理阶段初判 + 设计期确认 |

设计期才能确认的项（3/4/6）评不出时按「拿不准从高」处理，靠 §5 回写通道事后修正。

## 3. 需求级分级规则

| 级 | 判据（满足任一） |
|---|---|
| **A** | 命中 large-req-playbook 触发条件任一（涉及表结构变更 · 跨业务域 · 功能点 ≥5 · AI 判定为大型且用户确认）OR 影响面命中 ≥2 项 OR 涉数据迁移回填 |
| **B** | 影响面命中 1 项（**含配置类改动**——配置错误可全局故障，不入 C） |
| **C** | 影响面零命中，且改动**仅**纯展示/文案类 |

## 4. FR 级分级与聚合

- digest §7 规则表第 5 列「分级」：FR 级 = **所属功能点**的影响面判定，归属按「出处」列回溯 §4 功能点地图（§4 行内可标「（影响面：X）」注记）；仅纯展示/文案类规则为 C，计分/统计口径类至少 B。
- 双向追踪表中的非 FR 行（状态机迁移边、功能点矩阵来源）按所属功能点分级。
- **聚合公式**：需求级 = max(评分卡判定, max(FR 级))——FR 全员低不抵评分卡命中；FR 有高必上调需求级。

## 5. tier 回写与上调通道（只升不降）

影响面 3/4/6 是代码级事实，梳理阶段结构性评不出；「按 B 级跑轻量评审」的前提是事后发现判低了能立即升回来。

- **触发源**（任一发现影响面证据即触发）：设计文档影响面章节（playbook stage2 公共资产清单/接口契约分级）、sdlc-gate Step 1 双重判级（cases 头 + 对照 design 影响面章节）、sdlc-test static 阶段（代码定位发现公共组件引用/契约变更）。
- **规则**：tier **只升不降**；升级必须附证据（影响面命中项 + 出处）；回写 digest 头「风险分级」（升级依据+日期），并同步 cases 头与 issues 头。
- **B→A 补偿**：gate 已按 B 级跑完 2 子代理后发现应升 A → 补扇出被裁角色（#1 架构一致性、#3 测试可测性），交叉审查者结果保留。

## 6. 存量回退与 guard 口径

- digest/cases/issues 头字段名统一为「风险分级」（不写「风险等级」），取值 A|B|C。
- **无字段 = 未分级 = 按 A 级保守处理**，并提示用户补标（沿「存量不回改」先例，不迁移旧产物）。
- guard_exec 三口径：字段整行缺失 → 提示「按 A 继续」不拦截（保住在途项目）；字段存在但空/坏值/非 A|B|C → 拦截；digest 头与 cases 头均有值且不一致 → 拦截（升级未同步是高风险漂移）。
