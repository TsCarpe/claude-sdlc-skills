# 体检报告 + PM 确认清单模板

> 第二段「需求体检」的输出模板。产出两个文件，均写入 `sdlc/<需求名>/intake/`。
>
> **可读性原则**：报告是金字塔结构——全文唯一的成段文字在执行摘要，其余全部表格化；读者先读第 1、2 章即可掌握全貌，第 3 章按层跳读。

---

## 目录

- 文件一：体检报告（五章结构：执行摘要 / 阻断项速览 / 问题明细按层 / 主题关联 / 处理状态汇总）
- 撰写规则（编号、层列、列宽、排序）
- 终检（三项：统计表重数 / 跨文件计数一致 / 主题组关联核对）
- 文件二：PM 确认清单（三层结构：优先级档 → 主题组 → 问题表格）
- 交互标记约定（状态列取值与流转）

---

> ID 体系：本文件产出 体检.P<编号>（实例 P01）；其他产物引用本文问题须写 体检.P04（PM 清单族内可裸写 P04）

**撰写规则**：
- 编号 P01 起全局连续，按层序分配（不按严重度重排，保持稳定引用）
- 「层」列写「序号+层名简写」（如 `2 状态机`、`3 数据字段`、`5 角色覆盖`），禁止只写数字
- 明细表列宽控制：「问题与建议澄清方向」一句话说清问题+后果，用 `→` 连接澄清方向；「原文定位」= 章节名 + 「关键引文片段 ≤20 字」，禁止整句引用进表格；来源为评论时写「评论区」+「评论内容或锚点文字片段 ≤20 字」
- 层内按严重度排序（🔴→🟡→🔵）
- 某层无问题时保留章节标题，写「本层未发现问题」
- 主题关联章只聚合真实有脉络的问题，不硬凑

**终检（两个文件产出后、展示摘要前必过）**：

1. **统计表重数**：第 1 章统计表按第 3 章明细表逐条重新计数，不沿用草稿阶段数字
2. **跨文件计数一致**：PM 清单头部的分级计数（🔴N/🟡N/🔵N）必须等于体检报告第 1 章统计表合计行的对应数字
3. **主题组关联核对**：PM 清单每个主题组的「关联 Pxx」逐条回查体检报告，确认编号指向的问题内容确实归属该主题（PM 清单的分组主题名与报告第 4 章一致）

## 文件二：pm-checklist-<YYYYMMDD>.md

设计目标：**产品经理不需要打开需求文档就能逐条回答，并能直接在文件上作答**。三层结构：优先级档 → 主题组 → 问题表格；主题复用体检报告第 4 章的划分与命名，两文档可互相索引。

```markdown
# <需求名> 待确认问题清单

> <日期>整理 ｜ 共 N 问（🔴N/🟡N/🔵N）· N 个主题 ｜ 可直接在「答复」列填写后回传；带 🔴 的不澄清无法开始技术设计，盼优先回复

## 🔴 必须确认（N 问）

### <主题名>（n 问）｜关联 Pxx/Pxx

| # | 问题 | 答复 |
|---|---|---|
| 1 | <1-2 句自包含问句，内嵌关键冲突（「A 处写 X，B 处写 Y，以哪个为准？」）> | （待填写） |

### 其他（散题无主题可归时放各档末尾，不硬凑主题）

## 🟡 重要（同结构）

## 🔵 可顺带（同结构）
```

撰写规则：
- 主题组标题 = 主题名（与体检报告第 4 章一致）+ 问题数 + 关联 P 编号（PM 可忽略编号；开发侧用于回收后回写体检状态列）
- P 编号引用边界：intake 产物族内（digest/audit/pm-checklist 互引）可裸写 Pxx；其他产物（技术设计文档、review issues、测试用例）引用须写 体检.P<编号>（如 体检.P04）
- 每条问题引用具体冲突原文（「A 处写…，B 处写…」），让 PM 不用回查上下文
- 一条只问一件事；同一问题的多面拆成子问 a/b/c
- 不带技术实现倾向（问业务规则，不问怎么实现）
- 「答复」列初始为（待填写）；PM 回传后答案经确认回写体检报告状态列与梳理文档假设清单

## 交互标记约定

体检报告「状态」列的取值与流转，用户回应后更新（第 5 章汇总同步刷新）。**回写纪律：状态列每次更新时，第 1 章统计表与执行摘要的计数/结论必须同步刷新**（计数以第 3 章明细为唯一权威）——防止「PM 已答复但摘要仍计为剩余阻断项」的失同步：

| 标记 | 含义 | 后续动作 |
|---|---|---|
| `[ 待处理 ]` | 初始状态 | 无 |
| `[ 问PM ]` | 用户拿去和产品确认 | 等结论回填 |
| `[ 按假设X ]` | 用户拍板按某理解处理 | 回写梳理文档假设清单「结论」列 |
| `[ 忽略 ]` | 用户判定不成立/不做 | 保留记录，不再跟踪 |

全部阻断项都有结论后，体检闭环；假设清单的共识版即为后续技术设计的输入。未闭环项（非阻断遗留 / 用户暂不处理）由技术设计文档头部「体检问题去向」小节承接——sdlc-gate 已将其作为设计文档的前置校验。
