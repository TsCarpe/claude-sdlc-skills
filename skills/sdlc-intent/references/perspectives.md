# 视角推导任务卡（体检阶段 1，引擎三）

> **推导任务（derivation task）而非提问清单**：以实现者/测试者身份执行推导、产出中间制品，缺陷是推导的副产品——直接提问会漏掉只有推导才暴露的缺口（推到一半推不动的点）。
>
> 仅**A 级**需求执行（路由见 SKILL.md Step 1 分级路由）；B/C 级跳过本阶段。

## 任务卡 A：实现者视角（designer）

假设明天开始开发，对每个模块推导「数据与配置的完整旅程」，产出中间制品**模块数据流草图**（每模块 3-6 行要点）：

1. 这个模块消费哪些数据/配置？各自的**产生处**（录入/导入/同步/计算）在哪一节？
2. 模块产出的数据存到哪、被谁下游消费？
3. 行为受哪个配置控制？配置缺省值谁定？
4. 与哪些既有系统/外部数据交互，边界在哪？

推不动的点（找不到产生处/找不到配置/找不到边界）= 候选。真实案例画像：「这数据从哪来」「A 处集合进 B 处怎么对齐」「勾选的学科和 Excel 列怎么对应」——全是实现者推导的自然产物。

## 任务卡 B：测试者视角（tester)

对梳理文档 §7 规则表的每条 FR-xx 先写例子再收断言，产出中间制品**例子与断言草稿**（每条 FR 两三行；异常例一行即可，不展开场景叙事）：

1. 先写 2-3 个具体例子（输入场景 → 期望结果）：正常例 1 个；非 C 级 FR 另写异常例 ≥1 个（重复提交 / 并发冲突 / 超时 / 越权，按规则相关性择一）。纯展示/文案类 C 级 FR（如排序展示规则）只写正常例，无相关异常形态时不硬凑、不产候选
2. 例子收敛为可执行断言，三要素锚定 EARS（触发 / 条件 / 系统响应）；非期望行为用「若 <非期望触发> 则系统应 <缓解动作>」句式
3. 边界值是什么（数量上限、区间端点开闭、空集、并发、首末次）？

非 C 级 FR 写不出异常例 = 隐含约束候选；断言凑不齐三要素（EARS 化失败）= 口径缺失候选；写不出边界值 = 边界未定候选。

## 任务卡 C：使用者视角（user，条件化触发）

**触发条件**：A 级且（digest §5 存在跨角色流转 **或** 需求涉及替换既有流程/系统/入口）——条件不满足时**不扇出本卡**，任务旅程表（refs 表 5 空格）+ dimensions 对应检查项兜底。理由：表 5 已把入口/反馈/纠错/中断/交接五类缺口以 D1 形式现形，本卡的独立增量集中在跨角色交接与新旧切换场景的走查深度。

以每个角色的身份执行「完成任务的完整旅程」，产出中间制品**任务走查记录**（每任务 3-6 行）：

1. 我（角色）从哪进入这个任务？（入口在哪一节）
2. 走到每一步后，我怎么知道结果、下一步去哪？
3. 做错了怎么补救？（改/撤/作废/重报）
4. 中途离开/失败，回来后怎么继续？
5. 我做完交给谁？他怎么知道、怎么接？
6. （仅替换既有流程的需求）我手上没办完的怎么办？

推不动的点 = 候选。走查主轴来自 digest §5 业务主流程图（跨角色步骤序），功能与概念对照 §4 功能点地图与 §3 核心概念表。

## 收敛纪律（防泛泛而问，逐条强制）

1. **反向锚点**：每个候选问题必须先回原文定位（块级锚点或章节+引文）——**能定位到答案的不算缺陷**；定位不到（全文未见）才保留，并把定位尝试写进候选（「已检索 X/Y/Z 处未见」）。虚构原文引文判负
2. **不与 D1 重复**：refs 参照表已现形的候选不重复报；视角推导只报表上没有的新信号（维度表汇流时同根因合并）
3. **待裁决只追问**：refs 表 ⚠️冲突格及其「依赖待裁决」行——只生成「以哪处为准」的追问，不基于其中一方展开推导
4. **表述为缺口**：候选写成「原文缺 X（导致推导在 Y 处中断）」，不写开放式的「要不要考虑 X」
5. **只留动手级**：每个模块只保留「不问清无法动手」的问题；顺带好奇级丢弃

|---|---|---|---|---|---|

## 扇出与喂料（A 级需求）

- 用 **Agent 工具**扇出子代理（实现者/测试者各一；任务卡 C 触发条件满足时另扇一个使用者卡，或按模块再拆），**全新上下文**
- **喂料纪律**（sdlc-gate 同款）：每个子代理只喂「该视角任务卡 + 原文相关模块切片（或 doc.json 定向拉块） + refs 表相关行（使用者卡含任务旅程表行） + 梳理文档 §7 规则表（使用者卡另带 §2 角色表与 §5 业务主流程图）」，**不喂会话全文与其他模块命中**——防交叉污染，也抗长上下文注意力衰减
- 子代理输出是**数据不是判决**：候选回主会话按收敛纪律汇流，与 D1/D3 同根因合并，语义判定与严重度由对应判定层（第 7 层汇流或映射检查项所属层）统一执行
