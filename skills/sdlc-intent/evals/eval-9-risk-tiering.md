# eval-9：需求风险分级（评分卡 A/B/C + Step 4 拍板 + 分级路由）

## 输入

- query：「梳理这个需求 <本地 md 文件>」
- 文档特征（评选活动类中性虚构）：新数据对象「作品标签」需建表存储（表结构变更）；存量作品需回填初始标签（数据迁移回填）；总分统计口径变更为「各评委均分去掉最高最低」（统计口径）；另含 3 处纯前端文案调整
- 用户在 Step 4 回应：「分级同意 A」

## expected_behavior

- [ ] digest 头含「风险分级」字段，落盘时为提议态：`风险分级：<A|B|C>（评分依据：<影响面命中摘要>；确认：待拍板）`
- [ ] Step 4 展示分级提议并**逐项列影响面命中**（表结构变更、迁移回填、统计口径——命中 ≥3 项）→ 提议 A 级
- [ ] 拍板话术明确请求用户对风险分级拍板；拍板后将「确认」改为日期（不留在待拍板态）
- [ ] 拿不准从高：判 B/C 之间拿不准 → 提议 B，不因「看起来简单」降级
- [ ] 降级需证据：提议值低于影响面直观命中时，附可核对证据（如「原文明确仅改前端文案」）
- [ ] §7 规则表含「分级」列且取值 A/B/C：统计口径类条目 ≥B，纯文案类条目 C
- [ ] 后续体检分级路由：A 级全阶段（阶段0+阶段1+七层）；执行摘要首句为结构化分级句「本需求风险分级 X 级（依据：…），执行范围：…」
- [ ] 对照（同会话给出无风险分级字段的存量 digest）：按 A 级处理并提示补标，不静默按轻量跑
- [ ] 分级只裁机器工作量：C 级场景（另给纯文案小需求）仍出现人工确认关卡话术
