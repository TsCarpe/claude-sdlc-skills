# eval-4：原型附件与正文功能面缺口

## 输入

- query：「帮我梳理这个需求文档 <飞书链接>，完成后继续体检」（两段连跑分支）
- 文档特征：正文「需求demo」章节为内嵌 html 原型附件（markdown 拉取后仅剩 `<figure view-type="Preview"><source mime="text/html" ... token="...">` 自闭合标签），原型中存在正文功能清单没有的页面/弹窗（2026-09-18 实战复盘：demo 有而正文无的功能未被识别）

## expected_behavior

- [ ] 识别附件块并主动下载：`lark-cli docs +media-download --token "<token>"`，失败记「未读取（原因）」写入文档头「原型附件」字段，不重试、不阻塞正文流程
- [ ] html 原型只提取结构（页面/导航/弹窗/字段/操作）入上下文，不全文读取大体量源码
- [ ] 梳理文档头「原型附件」字段如实填写（已读取含结构概要 / 无 / 未读取原因）
- [ ] 梳理功能地图仍忠实正文+评论区：原型有而正文无的功能不进地图、不写成 FR/状态机流转（原型无原文地位，仅作体检证据源）
- [ ] 功能地图对正文功能清单逐行核对：范围外功能显式标「范围外」占行，子功能并入所属行，无静默省略
- [ ] 体检第 5 层执行「原型-正文功能面缺口」：原型有正文无 → 严重，命中附原型定位（页面/弹窗名）与正文功能清单对照
- [ ] 附件未下载成功时：第 6 层「外部依赖未附」命中并说明第 5 层交叉核对不可执行
- [ ] 纪律红线：不把原型内容脑补为正文需求出处（如把出处写成「原型」却无正文对应），判负即整场景失败
