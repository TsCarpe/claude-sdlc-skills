# eval-14：触发链断节（第 2 层模式④）

> 官方 JSON 结构场景（CONTRIBUTING「evals 规范格式」）。断链动作防漏报、完整动作不误报（嵌入式锚点）。

## 输入（迷你 PRD，评选活动类中性虚构）

```json
{
  "skills": ["sdlc-intent"],
  "query": "对下面这份迷你 PRD 做需求体检（阶段 2）：\n\n【活动复盘报告】评选活动结束后系统自动生成活动复盘报告：报告状态包括「生成中」和「已生成」两种；已生成的报告可在活动详情页查看，内容包含参与数据统计与获奖名单两个板块。\n\n【报名表导出】组织者在活动管理页点击「导出报名表」按钮，系统即时生成 Excel 文件并下载到本地。",
  "files": [],
  "expected_behavior": [
    "「生成活动复盘报告」按第 2 层「触发缺失/歧义」模式④命中触发链五要素缺陷，产生触发类问题（阻断级）：动作只定义了结果态（生成中/已生成），但「评选活动结束后」的触发主体（定时任务还是管理员手动触发）、触发时机口径（结束后多久、以何事件为准）无条款",
    "追问覆盖链上缺口：通知接收者（报告生成后通知谁）、通知通道、点击通知后的跳转落点——五要素中缺失的每一项都应出现在澄清问题里，而非只问其一",
    "「导出报名表」是触发链完整的动作（主体=组织者、时机=点击、结果=下载），不应对它产生触发类问题（不误报锚点）",
    "触发链问题按选择题化纪律产出：触发主体歧义（自动/手动二选一）给 2-4 项选项而非开放追问"
```

## 判负红线

- 「生成活动复盘报告」未产生任何触发类问题（模式④漏检）——该动作两态齐全但触发链断节，正是回流条目要兜住的形态
- 对「导出报名表」硬造触发类问题（误报）
- 五要素只覆盖一两项就收束，未对链上其余缺口逐项追问
