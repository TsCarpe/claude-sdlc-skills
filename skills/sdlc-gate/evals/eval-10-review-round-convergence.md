# eval-10：复审轮收敛——继承注入 + 变更聚焦 + 轮数熔断

首轮放行后设计局部实质变更开启复审轮（r2）。考察三件事：上轮已裁决条目不被复读、扇出范围聚焦变更章节、三轮不收敛触发熔断呈报而非继续打补丁。

```json
{
  "skills": ["sdlc-gate"],
  "query": "<需求名> r1 已放行，设计文档 §3 接口契约有局部实质变更，重新走评审关口",
  "files": [
    "sdlc/<需求名>/review/issues-<日期>.md（r1：已放行；裁决 12 条：落改 7/驳回 3/权衡 2；备案 2 条，其一处置=下轮 revisit）",
    "sdlc/<需求名>/design/design.md（§3 接口契约实质变更；§6 部署方案与 §3 无关联未动）",
    "sdlc/<需求名>/test/cases.md（对应 §3 的用例同步更新，其余章节未动）"
  ],
  "expected_behavior": [
    "开启 r2（issues-<日期>-r2.md）：头部「上轮」行含 r1 文件名 + 继承摘要（裁决计数四桶 + 备案 revisit 条数）+ 本轮扇出范围章节列表",
    "子代理 prompt 输出段含「上轮继承」占位（标题 + 裁决 + 理由一行），不含原文摘引级别的注入",
    "扇出 ARTIFACT = §3 变更章节 + 受影响关联章节；完全无关章节（§6 部署方案）不进扇出；角色 4 交叉审查者仍读全量",
    "r1 已驳回且未被新变更推翻的条目不出现在 r2 裁决清单——子代理上报则 RECONCILE 按继承注入过滤；确需翻案的须引用上轮编号说明理由",
    "处置=下轮 revisit 的备案条目随 r2 继承注入并重新评估",
    "熔断场景（r3 仍产出高严重度新发现）：停止继续裁决落改，头部状态置「熔断」，向用户呈报「三轮未收敛，建议退回 sdlc-design 重考虑方案」，用户裁决去向"
  ]
}
```

## 判负红线

- r2 对完全无关章节（§6 部署方案）全量扇出
- 上轮已驳回条目无翻案理由重现于 r2 裁决清单
- r3 熔断后仍继续裁决落改，或熔断件被直接置「已放行」
