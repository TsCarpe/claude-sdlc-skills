# eval-5：风险分级路由（A/B/C 分档扇出 + 双重判级升级 + C 级自查闭环）

## 输入

- query：「/sdlc-gate 作品标签」；设计文档与 cases.md 均已定稿
- 场景一（B 级）：cases.md 头部「风险分级：B（确认：2026-09-26）」；设计文档无公共资产/接口契约变更章节
- 场景二（B→A 升级）：同上，但设计文档「接口契约」章节出现「复用既有评分汇总公共服务，新增调用方」
- 场景三（C 级）：cases.md 头部「风险分级：C」，纯展示/文案类改动（3 处文案 + 1 个按钮显隐）
- 场景四（存量）：cases.md 头部无「风险分级」字段

## expected_behavior

- [ ] 场景一：扇出且仅扇出 2 个子代理（#2 数据模型与 SQL + #4 交叉审查者），对抗 prompt 模板照用，交叉审查者仍唯一同时读设计与用例
- [ ] 场景二（双重判级）：Step 1 对照设计文档影响面章节发现公共组件证据 → tier 只升不降升为 A 级：回写 digest 头（升级依据+日期）并同步 cases/issues 头，按 A 级扇出 4 子代理——**不因已按 B 跑过而跳过升级**
- [ ] 场景三：不开子代理，主会话按 issue-template「C 级自查清单」五问逐项过（设计+用例两侧），命中产 issue、无命中写「无」
- [ ] 场景三：issues 头部「独立性」行如实标注「破坏：主会话自查（C 级）」，不自标「未读设计（交叉全效）」
- [ ] 场景三：仍产出 issues 文件并走 Step 4 裁决 + Step 5 放行 + check_trace 校验（关卡互认链不断）
- [ ] 场景四：无字段按 A 级处理（4 子代理），并提示用户补标
- [ ] 任一场景：issues 头部含「风险分级」行，与 cases 头一致
- [ ] 分级只裁机器工作量：C 级也不跳过人工裁决关卡（🔒 暂停等人仍出现）
