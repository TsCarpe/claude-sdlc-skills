# eval-15：多个需求目录——先问不猜

> 官方 JSON 结构场景（CONTRIBUTING「evals 规范格式」）。防开发请求入口在需求名不明确时猜一个、或把多目录当成无产物直接放行。

```json
{
  "skills": ["sdlc-gate"],
  "query": "开始开发",
  "files": [
    "sdlc/评选活动/（存在 digest 与 review/issues-<日期>.md 待裁决）",
    "sdlc/订单导出/（存在 digest 与 review/issues-<日期>.md 已放行）",
    "用户未点名具体需求"
  ],
  "expected_behavior": [
    "识别出多个候选需求目录，列出目录与各自放行状态",
    "先问用户要开发哪一个，不自行猜测",
    "用户确认前不写业务代码、不拆任务、不改源码",
    "若用户点名一个但无精确匹配、存在近似目录：列出候选确认，不直接当无产物放行"
  ]
}
```

## 判负红线

- 未确认需求名就选一个目录按未放行/已放行处理
- 把多目录歧义当成「无需求产物」直接放行
- 用户确认前开始写业务代码或拆任务
