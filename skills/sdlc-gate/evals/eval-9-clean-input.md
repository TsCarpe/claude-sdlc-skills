# eval-9：独立反例场景——干净产物应零误报（假阳性回归底线）

输入为人工确认健康的干净产物。本场景考察的不是「抓到多少」而是「不误报多少」：干净产物上冒出的高/中严重度条目就是预审假阳性，直接判负。与 false-positive-patterns.md（运行时校准材料）互补，本场景是改动预审 prompt / RECONCILE 规则 / issue 模板 / 分档规则后的必跑回归底线。

## 判负红线

- 干净产物上任何**高/中严重度**条目进入裁决清单——假阳性通道
- 为凑发现数把噪音/风格偏好放进裁决清单

## 干净产物构造说明（执行时按下述要求生成三份输入文件）

五类口径（字段长度上限、枚举值、状态流转、幂等、软删）在三份文件中逐条对齐且全部有定义——有定义即不构成「未言假设」类发现；设计不引入规则清单之外的新约束；用例断言不超出也不低于规则清单口径。

**「人工确认健康」前提不可省略**：构造方（含 AI）自检对齐不构成确认——实证中，AI 构造方自检通过的产物仍被对抗扇出揪出真分歧（首轮 24 条；按全量修复清单重写后二轮仍有多条，含两路独立采样各自发现的不同高严重度缺陷；每轮修复把机制写得更具体，又开出新攻击面：上调不唤醒候补、快照读超卖、用例不可证伪等）。fixture 生成后须逐条人工终审——每条规则在 digest/design/cases 三处逐字对照、每个用例断言可证伪、每条设计断言有承载与量化依据——确认后方可作为本场景输入。
