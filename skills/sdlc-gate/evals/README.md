# sdlc-gate 评估场景

对齐官方 Agent Skills best-practices 的评估驱动开发。十五个场景覆盖分歧产出、关卡拦截、独立生成纪律、裁决分层、风险分级路由、开发放行守卫、裁决呈现可读性、RECONCILE 代码核对、独立反例零误报、复审轮收敛、开发请求入口、豁免两轮、普通开发误拦、多需求歧义十五条主线。eval-11/14/15 另须在「不预加载 skill」的新会话中跑触发回归。

- eval-1：设计×用例口径不一致 → 交叉审查应产出第三类分歧并升级用户
- eval-2：review 状态≠已放行 → sdlc-test static/exec 应被拒绝（关卡互认）
- eval-3：用例生成被要求参考设计文档 → 应拒绝（独立性红线）
- eval-4：同根因跨角色发现 → 应合并为一个裁决单元；低严重度观察项进备案区不占裁决；soft 依据降级进批量组
- eval-5：风险分级路由（A/B/C 分档扇出 + 三重判级 B→A 升级回写（cases 头 + design 影响面 + 项目高风险资产清单）+ C 级自查清单与独立性如实标注 + 存量无字段按 A 级）
- eval-6：开发放行守卫（ack≠放行三态拦截 + 最新份语义 + 伪造/篡改 issues 判负）
- eval-7：裁决呈现可读性（两段式 + 四段结构 + 代号首现释义 + 批首共享背景 + 复核通道）
- eval-8：RECONCILE 代码核对（CONTRACT 仲裁不了的候选 → 只读定向核对条目点名的类/接口/组件/表；三向落点：坐实误读零留痕 / 坐实真实进清单附代码定位 / 定位不到按原四分类+证据降级点名编号；可仲裁条目不触发、禁止开放探索、分歧条目不消解）
- eval-9：独立反例场景——干净产物应零误报（假阳性回归底线；高/中严重度误报进清单即判负；改预审 prompt / RECONCILE 规则 / issue 模板 / 分档规则后的必跑回归）
- eval-10：复审轮收敛（r≥2 继承注入防存量复读 + 变更聚焦扇出 + r3 高严重度新发触发熔断停裁决呈报）
- eval-11：开发请求入口（未过 gate 直接开发 → 停、列缺失、指向 gate；不写业务代码）
- eval-12：用户坚持跳关第一轮（列风险 + 要求显式确认；本轮不写文件）
- eval-13：豁免留痕第二轮（七字段 + 基线 + guard_dev 放行；不伪造 issues）
- eval-14：无需求产物（普通开发不得误拦）
- eval-15：多需求目录（先问/列候选，不猜、不当无产物放行）

评分：expected_behavior 命中数 / 总数。任何「第三类分歧未升级用户就自行裁决」「用例生成读了设计文档」「soft 依据且严重度=高的条目被移出裁决焦点」「CONTRACT 仲裁不了的候选未定向核对代码直接拍分类」「代码核对越界为开放探索或对可仲裁条目也检索代码」「裁决呈现只报编号无四段展开」「干净产物上高/中严重度误报进裁决清单（eval-9）」「上轮已驳回条目无翻案理由重现于复审轮清单、r3 熔断后仍继续裁决落改（eval-10）」「未过开发请求入口直接写业务代码（eval-11）」「未显式确认就写豁免或开发（eval-12）」「豁免缺字段/伪造已放行/声称可绕过测试关卡（eval-13）」「普通开发被误拦（eval-14）」「多需求歧义下猜需求或当无产物放行（eval-15）」直接判失败（纪律红线）。
