# eval-a：长会话产出交接卡

会话已进行到上下文将满：改过 4 个文件、跑过一次测试（部分通过）、有一条讨论后被否决的方案、还有一个待确认的外部依赖。用户说「交接一下吧，我换个会话继续」。

```json
{
  "skills": ["sdlc-handoff"],
  "query": "交接一下吧，上下文太满了，我换个会话继续",
  "files": ["src/export/job.ts"],
  "expected_behavior": [
    "先执行 collect.sh（或按 manual-collect.md 手工采集）拿到 git 硬事实，再动笔写卡",
    "落盘到 <项目根>/.handoff/YYYYMMDD-HHmm-<slug>.md，不覆盖已有交接卡",
    "frontmatter 含 task/mode/status/repo/branch/head/dirty_files/created/next，且 head 与 dirty_files 与实际一致",
    "正文 8 段齐全：目标与验收 / 已完成 / 断点 / 决策与已否决方案 / 改动清单 / 待办 / 未决问题 / 指针",
    "「已完成」每项显式标注 已跑通 / 仅编译 / 未验证，部分通过的测试不写成已完成",
    "记录被否决的方案及否决原因",
    "「指针」段记录会话记录路径或明确写不可达，后台任务写检查结果或「未检查」",
    "交付一句可直接粘贴的启动语「接手 <交接卡绝对路径>」，不写死某平台的斜杠命令"
  ]
}
```

## 判负红线

- 交接卡里贴了 diff、大段代码或原文照抄
- 把「未验证」或「跑了一半」写成「已完成」
- 正文超过 120 行，或单个代码块超过 10 行
- 缺少「已否决方案」段，或该段为空却声称写完了
- 覆盖了已有交接卡
- 启动语写成某个平台专有的斜杠命令或恢复命令
