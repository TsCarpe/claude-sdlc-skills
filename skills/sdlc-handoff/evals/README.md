# sdlc-handoff 评估场景

交接技能的行为评估是**人工场景**（无自动运行器）：把 `query` 与 `files` 交给一个新会话，对照 `expected_behavior` 逐条判定；命中任一「判负红线」即整场景失败。

| 场景 | 覆盖 | 关键判负 |
|---|---|---|
| eval-a（`eval-a-write-from-long-session.md`） | 长会话产出交接卡：先采集硬事实再动笔、8 段齐全（含背景三件套与操作须知）、验证状态显式、prev 继承、接手者五问自检、启动语平台无关 | 贴 diff / 未验证写成已完成 / 覆盖旧卡 |
| eval-b（`eval-b-resume-no-redo.md`） | 新会话凭卡接手：漂移校验 + 四要素接手确认 + 断点复核 + 直接执行 next + 活卡留痕 | 让用户重述 / 重做已完成步骤 / 不校验就开工 |
| eval-c（`eval-c-drift-after-handoff.md`） | 交接后代码漂移：head 非祖先、dirty 数不一致、断点位置核对 | 漏报漂移 / 自动回滚文件 / 因漂移终止 |

补充人工场景（一行清单，无独立文件）：

- manual-d：项目不是 git 仓库 → 交接卡应写「无版本控制」并改用文件时间清单，不得伪造 branch/head
- manual-e：`next` 本身有歧义 → 只问一个具体问题，不得把整份背景再问一遍
- manual-f：用户在同一会话内只是嫌历史长 → 应建议用 agent 自带的上下文压缩，而不是走交接
