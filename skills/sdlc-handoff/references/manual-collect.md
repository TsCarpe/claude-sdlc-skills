# 无脚本时的等价采集

`collect.sh` 不能执行（环境无 bash、无 git、或工具集禁止 shell）时，用 agent 现有工具做同样的采集。目标不是逐字节复刻，而是**不漏字段**。

## 一、项目与分支

| 字段 | 采集方式 |
|---|---|
| 项目根 | `git rev-parse --show-toplevel`；非 git 用当前工作目录 |
| 分支 | `git rev-parse --abbrev-ref HEAD` |
| 提交 | `git rev-parse --short HEAD` |
| 上游领先/落后 | `git rev-list --left-right --count @{u}...HEAD`（无上游则跳过） |

## 二、改动

| 字段 | 采集方式 |
|---|---|
| 改动文件数 | `git status --porcelain` 的行数 |
| 改动明细 | `git status --porcelain`（超过 40 行只保留前 40 行，并在卡里注明截断） |
| 规模概览 | `git diff --stat`（超过 30 行同样截断注明） |
| 未提交但已暂存 | `git diff --cached --stat` |

非 git 目录：改为列出最近修改的文件（按修改时间排序，最多 20 个），并在卡里注明「无版本控制，改动清单来自文件时间」。

## 三、最近提交

`git log --oneline -8`。用途是给新会话一个「最近在动什么」的锚点，不要展开 diff。

## 四、会话记录（可选增强）

1. 先看环境变量 `HANDOFF_SESSION_DIRS`（冒号分隔目录），在其中找 `*.jsonl`。
2. 没有配置时不必到处搜索；直接问用户「旧会话的导出文件在哪」，或把 `session_ref` 留空。
3. 拿到路径后记进 frontmatter 的 `session_ref`；resume 端用它跑 `digest_transcript.py`，读不到就跳过。

## 五、已有交接卡

扫描 `<项目根>/.handoff/` 与 `~/.handoff/` 下的 `*.md`，按修改时间倒序取前 5 个，报告「时间 / task 字段 / status 字段」。目的是避免重复造卡、也能发现上一张卡还挂着。发现**同任务存续卡**时，把最新一张的路径记下来——写卡时填进 frontmatter 的 `prev`，并继承其「背景与目标」与未结待办。

## 六、后台任务与临时产物

- 后台任务：工具集提供进程/任务列表就查，记录仍在运行且与当前任务相关的项（命令 + PID + 一句话用途）。
- 临时产物：`HANDOFF_SCRATCH_DIR` 若设置则列顶层 10 项；否则回想本次会话写过的临时文件，把路径记进「指针」段。
- 两者都拿不到时，在卡里如实写「未检查」——不要留空让新会话误以为不存在。

## 七、填卡顺序（省 token）

1. 先写 frontmatter（全部来自上面的事实，不需要思考）
2. 再写第 3、5、8 段（断点、改动、指针与操作须知——纯事实）
3. 然后写第 1、2、6、7 段（背景与目标、已完成、待办、未决）——背景可从 prev 卡继承后按现状改写
4. 最后写第 4 段（决策与已否决方案）——这段最费脑，放最后不阻塞其他段
