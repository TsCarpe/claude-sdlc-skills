# eval-6：不带子命令时的命令表要带完整例子

```json
{
  "skills": ["sdlc-platform"],
  "query": "/sdlc-platform",
  "files": [],
  "expected_behavior": [
    "不调用任何 MCP 工具，不先问迭代名，不问「想做哪一步」",
    "第一句是「开场白」原文（产物平台帮您把原始需求经过质检和澄清，变成可直接交给开发的标准需求文档。）",
    "原样给「给用户看的命令表」：四列「步骤 / 操作 / 命令示例 / 说明」，主流程按 1–8 排序，查进度、看原文、导入需求标「随时」排在最后，除「新建迭代」写「见下方模板」、「导入需求」写「到产物平台上点「重试导入」」外，每一行的「命令示例」都是完整可发的命令，例如 /sdlc-platform status v1.0-登录",
    "new 那一行命令示例写「见下方模板」，表后给引导句和五行模板代码块（/sdlc-platform new、迭代名：、项目名称：、需求名：、来源：各占一行）；其余行带示例迭代名 v1.0-登录",
    "表里不出现 new [迭代名] 这类方括号占位写法，不出现 MCP 工具名或「调用」列",
    "表后原样附两条说明：替换为实际迭代名；来源可直接粘贴需求原文，也可提供飞书文档链接。不出现「直接发」字样",
    "最后说「没写子命令」那一句原文：建议从第 1 步开始按步骤执行，并提示可随时用 status 查进度"
  ]
}
```

## 判负红线（任一命中整场景失败）

- 只问迭代名、不给命令表
- 以「您想做哪一步」之类的提问收尾，而不是建议从第 1 步开始
- 命令表里用 `[迭代名]` 占位而不给完整例子
- 把 `sdlc-in:` / `sdlc-out:` 工具名展示给用户
