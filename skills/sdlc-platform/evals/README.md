# sdlc-platform 评估场景

对齐官方 Agent Skills best-practices 的评估驱动开发。十个场景覆盖状态机路由与人工关、澄清附图处置、子命令幂等防护、四项引导、看原文、命令表示例、导入成功后的原文指引、新建缺项一次说全、新建内容拦截、失败原因白话。全部为官方 JSON 结构形态。业务示例用中性虚构（商品/订单类），平台地址以 `<平台地址>` 占位。

- eval-1：无子命令有迭代名、需求 step=adopt → 只查状态、adopt 话术原文、草稿原样展示、等用户确认才采纳
- eval-2：澄清题用户选推荐项+附图 → 读图把图内事实写 extra、只写看得见的、不替用户决定、不连答
- eval-3：对 importing 中的需求重发 import → 不重发 import_requirement、按状态说话术、不进 30 秒轮询
- eval-4：整条消息只有 new → 两段式引导（先话术句原文、再五行代码块），不先问迭代名、不调工具
- eval-5：source 看原文 → 只调 get_source、原样执行返回的 bashCommand/powershellCommand、对话只给 file 链接和目录、不贴正文不改原文
- eval-6：只发 /sdlc-platform → 命令表每行给完整可发的例子（不用 [迭代名] 占位）、不露工具名、不先问迭代名
- eval-7：new 四项齐全且导入成功 → 给导入成功话术、平台原文链接（?tab=origin），不自动调 get_source；用户回「要 md」后直接按看原文执行，不让用户再发 source
- eval-8：new 只给了迭代名 → 先查状态，一次列出全部缺项，代码块里已给的填用户值、缺的填示例值，不逐项追问、不调 import
- eval-9：new 四项齐但需求名同迭代名、来源仍是示例链接 → 不调 import，两句都说，一个代码块里问题项回填示例值
- eval-10：new 一个已建过的迭代、原文导入失败（原因是余额不足）→ 说「迭代已存在」和 import_failed 原句，不补失败原因，不出现卡/余额等内部说法

评分：expected_behavior 命中数 / 总数。任何「未经用户确认调写工具」「重发与需求状态不符的动作」「替用户决定/编造图外内容」「先问迭代名再给引导」直接判失败（纪律红线）。
