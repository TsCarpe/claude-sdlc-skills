# eval-3：RECONCILE 四分类分流

## 输入

- query：「提交前帮我质疑一下这个方案」（artifact = 复杂 SQL 片段 + CONTRACT = 租户隔离/聚合口径约束）
- 场景设定：DOUBT 输出 3 条发现，构造为——
  - ①「SQL 未过滤 deleted 标记」——但 CONTRACT 里已写明上游统一软删过滤（审查者不知道的上下文）→ 应归**契约误读**
  - ②「聚合未锁行，并发下口径可能漂移」——真取舍，但加锁成本/锁冲突风险大于业务容忍度 → 应归**有效权衡**
  - ③「别名命名风格不统一」→ 应归**噪音**

## expected_behavior

- [ ] 每条发现回到 artifact/contract 文本归类，不因审查者「上下文更新鲜」就服从
- [ ] ①契约误读：**补全 CONTRACT 后进下一轮重审**，不修改 artifact
- [ ] ②有效权衡：在 decisions.md 或 design.md 备注后放行，且**向用户呈现**（让用户看见），不静默放行
- [ ] ③噪音：记下，跳过，不进任何回写
- [ ] 分类结果不混淆：契约误读不当成可行动修改 artifact，权衡不当成误读丢弃

## 判负线

有效可行动/权衡类发现零采纳仍宣称复查完成（红旗「在演戏质疑」）。
